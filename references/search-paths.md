# 检索路径库（活水地图）

供信息采集、创意补证、案例拆解、专业原文读取与视觉取材时调用。研究在任务中的位置、与创作/生产/反馈的衔接按[主定义“二、研究接口”](research-and-content-production-loop.md)执行；旧 Step 1、Step 5 是可复用的调用位置，不要求每次按固定步序走完。核心一句话：**按关键问题选择足够的信息源，实际执行、读取、反证并留下可追溯记录；访问受限时换路，不能把检索计划冒充研究结果。**

本文件是“活水地图 + 来源路由”，不是采集保证书。具体访问、登录、截图、降级和证据状态按 `source-access-and-login-workflow.md` 执行；来源数量、声明强度、反证和置信度统一按 [证据规则](anti-hallucination-and-evidence.md)“三点二、按声明性质决定证据要求”“三点三、主动反证与置信度”执行。

## 一、先判断要什么（信号路由）

检索前先问：这一步要的到底是哪种信息？不同问题，去不同源，别搞反。先从brief提取待回答的问题及将受影响的内容；地方文化查原始资料，专业演示查产品/技术资料，行业标准查发布机构与适用条款，创作参考看完整作品/机制。外部案例只能补证，不能取代客户已提供的真实内容。

批量检索先查项目续接入口及已有产物，明确本轮缺哪个答案，再决定搜索范围。文件搜索先用 `rg --files -g ...` 或 `rg -l` 定位候选，再用带路径和上下文范围的 `rg -n`/局部读取；不要先拼接整个仓库、全部reference、全部会话或所有工具说明。目录、备份、生成物和缓存按问题排除，若它们正是目标再定向读，不能一概忽略原始证据。

读取范围由关键问题、证据缺口和材料结构决定，不规定候选文件数或每次行数。正文过长时按章节、页码、检索上下文或工具分页分段读取，保留已读位置、未读范围及续读入口。检索结果很多时把完整匹配保存到项目资料文件，模型先接收结果数、相关位置、必要片段及文件入口，再按判断所需读回原文；返回上限与分页位置要明确，不能将第一批当全部。避免含 base64、压缩 JSON 或单行 HTML 的整行输出，先提取所需字段/段落再返回。工具的 `max_output_tokens` 只是最后保险，不代替分段读取；出现截断须补读，未读部分保持未读。上下文管理服务研究完整性，不得以节省 token 为由省掉关键材料、反证或内容生产。

独立问题和来源路径可以并行，将原文、检索明细和核心产出保存在文件中，返回可恢复的索引，避免同时回灌大批全文。研究覆盖仍以关键问题与证据缺口为准，不因并行返回预算减少必要核验。同一已读且未改动的材料复用路径、版本与摘要；需要具体依据时读回原段。短摘要只用来选择下一次读取，按 `source-access-and-login-workflow.md` 维护续接。

### 一点一、实际拆关键词，再选路径

关键词从本次问题拆出，不能只写“搜索相关案例”。下表是检查维度；按任务需要组合，不要求每条 query 塞满所有词。

| 维度 | 具体拆法 | 要避免的误判 |
|---|---|---|
| 身份与别名 | 项目/品牌/活动的官方名、简称、旧名、运营方、主办方、人物或作品别名 | 同名项目、名称改版或承办方被当成同一主体 |
| 地域与场景 | 城市、区县、地址、目的地、商圈、场地类型；迁移案例时另列市场/国家 | 异地同名命中或不同生活半径直接套用 |
| 周期与日期 | 年份、届次、档期、持续周期、工作日/周末、开业/在营时期；区分检索日期和事件日期 | 旧活动被当成当期、报道日期被当成发生日期 |
| 人群与动机 | 实际参与者身份、到访目的、所得、时间成本、消费/社交/表达动机，沿用其真实用语 | 只搜人口标签，漏掉为什么参加或离开 |
| 机制与生产 | 参与动作、任务规则、共创/揭晓/接力、商户承接、内容轮换、拍摄/舞台/材料/交付关键词 | 只搜主题名或漂亮标题，未读实际运作条件 |
| 阻力与反向词 | 排队、收费、交通、取消、投诉、尴尬、体验差、失败、限制、未兑现，以及本任务具体失效条件 | 仅收成功叙述，或把未搜到负面当不存在 |
| 同义与中英文 | 行业术语、俗称、原语种/英文名、动作同义词及可迁移机制词；核对语义后扩展 | 机械直译导致错义，或漏掉原语种资料 |

先用身份、地域、周期核对对象，再按问题增加人群/机制/阻力词。例如可执行的 query 结构是 `项目别名 城市 年份 排队`、`活动名 主办方 规则 site:已核实的官方域名`、`机制原语词 participation rules case study`；替换为本项目实际词，记录真正提交的字符串。结果不足、同名混淆、只剩转载或样本偏向时，检查是哪一维缺失，再扩展/收窄词、时间、地域、源或语言，不能机械重复同一 query。

检索前建立简短计划：`问题/将影响的判断 → 关键词组 → 拟查源与理由 → 尚缺证据`。执行记录按[访问工作流](source-access-and-login-workflow.md)“七点一、计划与执行分开记录”填写。计划和执行分开；真实发生的查询、访问、读取分别记执行动作与结果。提交 query 不等于已打开或已读命中，失败查询也须保留执行记录。

| 要什么 | 优先源与动作 | 不能据此推出 |
|---|---|---|
| 项目身份、事件存在、规则与权益 | 主办/运营/品牌/政府官方原页及原始文件；核对适用日期与条款 | 宣传承诺已履约、同名对象相同、官方自报等于独立效果 |
| 案例机制与创作参考 | 官方/制作方完整作品、规则与过程材料；数英网 / SocialBeta / 广告门等案例库补充；按缺口找参与者体验 | 标题或新闻稿证明完整机制、案例适合本项目 |
| 用户真实口碑 | 按实际客群使用的平台站内搜索、评论/弹幕/长评，或授权的一手反馈；寻找相反体验 | 官方宣传等于口碑、可见样本等于全体用户 |
| 热点趋势与创意碰撞信号 | 可访问的热榜、话题与讨论原页，结合发生时间、参与动作和情绪语境 | 单日榜单证明长期趋势、标题证明真实参与或适用性 |
| 行业规模、标准与专业事实 | 政府统计、发布机构、行业协会、原始报告/技术资料；数据平台须核口径与权限 | 聚合摘要或自媒体猜测证明数值、转载数量证明独立性 |
| 视觉与制作取材 | 主办方、场地、品牌、设计/制作方发布的原图/图集/图纸/视频；实际打开相关页、图或帧 | 搜索缩略图证明全貌、效果图等于现场、文本读取等于看过画面 |

铁律：要口碑、反应、真实想法，不能只用搜索引擎搜新闻。新闻稿经常夸大、漏掉真实用户声音。

## 二、来源可访问性分层

| 层级 | 含义 | 示例 | 采集方式 |
|---|---|---|---|
| A 类：公开网页源 | 普通联网搜索或网页访问通常可验证 | 政府官网、品牌官网、公开新闻、公开行业报告、部分案例库页面 | 联网搜索、网页读取、链接核验 |
| B 类：浏览器验证源 | 需要站内搜索、滚动、点击、截图、评论区核验 | 小红书、抖音、微博、B站、知乎 | 浏览器自动化；必要时用户登录 |
| C 类：登录/权限/付费源 | 需要账号、会员、后台、机构权限或 API | 蝉妈妈、QuestMobile、卡思数据、新榜后台、舆情监测平台 | 需账号权限；不可访问时标待验证 |

B/C 类是真实来源，但不等于稳定可自动采集。抓不到、登录墙、403、验证码、内容不支持判断时，必须按 `source-access-and-login-workflow.md` 降级。

## 三、按声明选择并迭代多源路径

没有对全部问题有效的固定平台先后顺序。身份、日期、官方规则、产品参数、统计口径与标准条款优先找发布主体原文；口碑、参与动作和体验阻力优先读目标客群的站内内容或授权反馈；创意机制读完整作品与运作材料；视觉判断走可实见的原图/页/帧路径。一个问题可以同时需要这些不同材料。

1. **选择主路径**：写清待证声明、来源为何能回答及原文应在哪里。站内搜、官网目录/公告、搜索引擎、专业接口各按用途使用。
2. **执行并读原文**：搜索引擎及 `site:` 可定位或补漏；搜索摘要只作线索。对关键命中打开原页，核对身份、日期、上下文和实际可见范围。
3. **换路与补缺口**：无命中、仅转载、原文失效、登录阻断、语言或地域偏差时，记录失败原因与未解决问题，再换词、源、站内入口、原语种或授权材料。可在主路径之外并行补专业资料、相反体验或制作条件。
4. **核对来源独立性与判断**：记录首发/原始来源及转载关系。多家新闻转载同一通稿、同一报告或同一组数据，按同一证据链处理，不能作为多次独立印证。说明新材料支持、削弱或改变了哪一判断，哪些缺口仍保留。

是否继续搜索由关键判断是否有足够匹配证据、是否存在相反解释及剩余缺口的决策影响决定，不以凑平台数、方向数或结果数结束。无法访问时保留限制并推进可做部分，不能把换路后的可见标题写成完成原目标采集。

## 四、中文活动策划的检索路径

### 案例 / 灵感源

- 数英网、SocialBeta、广告门、新榜公开内容、卡思公开报告：搜“品类词 + 活动词”。
- 品牌官方账号（公众号 / 微博 / B站 / 官网）：看品牌自己如何定义活动和传播口径。
- 同类活动复盘、参会者笔记、媒体原创报道：拆机制，不照搬环节。

### 用户口碑源

- 小红书：站内搜“品类 + 活动词”，看笔记与评论；未登录时先检测能否看到结果。
- 抖音：搜话题/作品，读取实际可见的内容、评论和互动；公开互动不能推算不可见完播率、受众去重或到访。后台指标仅在授权且实际取得时使用。
- 微博：搜活动话题，看实时讨论、转发链、吐槽和媒体扩散。
- 知乎：搜相关问题，看长回答与争议点。
- B站：搜活动视频，看弹幕、评论区、二创和长评。

公开消费口碑按关键判断选择相关平台或授权的一手反馈，主动寻找不同客群、时段和相反体验；不以平台数量作为验收线。只有一个平台可读时，写清样本和访问限制，不能以反复出现代替独立印证。纯内部、保密或小样本活动优先授权反馈，不搜无关热榜补数。

### 热点趋势源

- 微博热搜、抖音热榜、新榜日榜、百度指数。
- 创意确需热点输入时，先按 `source-access-and-login-workflow.md` 检测热点源访问状态，读取讨论语境和时间，再提取热点背后的情绪供交叉网络使用。借势不是贴热点名，而是把实际可证的情绪喂给 H 热点域和 E 情绪域。

### 行业数据源

- 公开报告、行业协会、政府统计、公司财报、品牌官方数据。
- 蝉妈妈、QuestMobile、艾瑞、卡思数据、新榜等平台需要先判断公开可见、登录可见、付费可见还是权限不可达。
- 没有权限时，不得编行业数据，只能写“需账号权限/待验证”。

### 非消费端垂直源

消费端源不适合所有活动。政企招商、校招、危机公关、开工仪式、线上活动要换源。

| 活动类型 | 垂直源 |
|---|---|
| 政企招商 / 政府关系 | 政府官网、招商局网站、产业园公告、地方党媒 |
| 招聘 / 雇主品牌 | 招聘平台、脉脉、牛客、雇主品牌报告、Glassdoor 类点评 |
| 危机公关 / 舆情 | 舆情监测平台、主流媒体评论、监管公告、黑猫投诉 |
| 仪式型（开工/签约/揭牌） | 政府新闻、行业垂直媒体、地方电视台 |
| 线上 / 混合活动 | 平台线上活动数据、完播率/参会率数据源、B端活动平台 |

## 四点五、商业地产地址研究与系列案例路由

商业地产项目先按 [统筹模块](series-campaign-orchestration.md)“三、项目研究与案例迁移”建立项目诊断，再进入案例和创意。每条研究信息在既有内部研究索引中保留 `source_id`、来源链接、读取范围、状态和影响的决策；索引按本次用途选择文件，不强制建立工作簿。

| 研究对象 | 优先材料与核查动作 | 形成的判断与限制 |
|---|---|---|
| 地址与项目身份 | 核对项目官方页、地图、地址别名、运营方及开业/在营状态；同名项目要交叉确认城市和地址 | 明确本项目、可用场景和出入口，不把搜索首条当项目身份 |
| 交通与商圈 | 查公共交通、步行连接、停车及周边办公/居住/旅游/院校；条件允许用时段观察或甲方资料核对 | 按实际出行和消费行为提出商圈范围，不硬套半径；地图上有住宅不等于其居民已是项目客群 |
| 项目定位与租户 | 查当前项目介绍、租户目录、商户活动、营业时间；核心权益、店铺在营状态和库存需确认 | 区分品牌定位、公开租户事实、策划合作设想与已确认商户承接 |
| 竞品与替代去处 | 查同一生活半径、相似客群及同档期项目，含非商场目的地；研究活动、价格/体验和交通条件 | 说明受众为何选择这里、什么体验已经拥挤；未搜到活动不能等于竞品没有动作 |
| 历史活动与口碑 | 项目别名+活动名+年份检索，主动查看排队、交通、服务、消费、内容质量等相反体验 | 记录平台、检索词、时间范围、实际读到的样本、受邀迹象和访问缺口；不把样本变成总体好评率 |
| 履约条件与数据缺口 | 汇总甲方提供或待确认的客流基线、时段、场地容量、噪声/用电/搭建、预算、资源、租户权益和测量权限 | 公开资料不能替代现场核查或有权确认。条件不全时提出可行的条件式草案，未知保留未知 |

商圈人群输出分为已核事实、基于地理/业态/行为的客群推断、需甲方提供或采样的数据。每个推断注明会改变哪个活动单元、邀请资源或传播入口，并说明最小核验方式。公开评论的主动反证记录与未发现/受限状态按证据规则，不制作负面配额。

系列案例按本项目缺口选择和迭代，以下为可组合路径，不要求各层凑固定数量或全部走完：

1. **本地近似项目**：优先同城、相近场景、客群与周期，了解交通、时段、体验和商户承接的实际边界。
2. **国内同类**：拆总主题、持续资产、重点场次、内容轮换、创作者任务和国内平台参与动作。
3. **国外可迁移机制**：寻找持续公共体验、公众共创、揭晓接力、商户联动等机制，核对规则和资源条件，说明国内适配差异。

每个采用的案例写清：发生日期与周期、场景、内容更新、参与动作、可生产的传播素材、创作者角色、商户承接、已知成本条件/未知项、效果证据及原始链接。未公开费用不猜报价；活动存在与官方自报效果分开，实际增量不得由报道热度推导。最后必须回答“这条资料改变了本方案的哪项判断”；不能只交网页链接目录。

## 四点六、行业入口与充分性（来源目录主定义）

商业地产系列事件营销默认从公开来源开始。以下是按问题调用的核心入口与可扩展候选，不是封闭白名单，也不是每项目全站必扫表。项目及运营商、商户、场地、当地政府/交通、艺术家、设计制作方和目标客群使用的新社区，按实际地址、人群、机制与档期加入。登录、付费、后台和甲方内部材料为关键缺口的条件扩展，不假定已有权限，不自动购买。

来源登记的最小接口是：`用途/待证问题、入口URL或真实资料路径、发布主体与角色、适用地域/事件及统计时间、访问方式与实际范围、能支持/不能支持的声明、替代路径、核验日期、相关source_id/action_id`。未定位的项目地址或账号保留“待定位”，未实际访问的候选保留“未核验”，不能预填可读。主页或导航可读只证明入口的该部分，不证明全站资料、评论、附件或后台可用。

### 四点六点一、充分性与再检索

以“项目身份/定位与租户、来访人群及阻力、同档期替代、系列内容与素材、创作者匹配、兑现条件、传播与经营测量”中的适用问题做覆盖检查。每项必须有足以支持当前声明的证据、合理推断及其最小核验动作，或明确的未解决缺口；不要求每个问题都拿到现阶段不存在的数据。先核第一性条件：用户实际所得和成本、内容能否生产、资源能否兑现、目标是否可观察；网站数量只能描述检索动作，不能替代这些判断。

横向比较相近地点/客群/档期的不同机制和替代去处；纵向追同一系列的预热、场次、变化、兑现与后续，含不同年份的版本区别。对决定客群、组合、预算和效果的判断找相反体验或替代解释。材料能否改变某项决策是继续搜索的依据，不为满足栏目名强行凑案例、平台或网站。

没有统一“所有行业网站”。来源要随地址、租户、节目、地区、媒介和时间扩展；未列网站提供更合格的一手证据时直接加入。样本受邀请、同通稿转载、主办与合作方共源、同报告被不同媒体引用分别记来源关系。登录/风控阻断后的具体换词、站内路径、原语种或替代原文必须记录动作及结果；只写计划不能提升证据状态。

## 五、反模式

1. 用新闻稿/官方宣传代替真实口碑。
2. 把单个平台的已读样本说成全部客群的总体结论。
3. 报数据不引用原文或访问状态。
4. 过滤负面评价来“平衡”。
5. 不查一手来源就用二手转载。
6. 把登录墙、搜索结果页、热榜标题写成完整事实。
7. 让用户自己去搜资料，而不是 AI 先验证再请求最小介入。

## 六、来源验证

交付对标先问“这份文件服务哪个动作”，再找同用途、近阶段、可见深度足够的样本。优先客户真实模板/往届工作件、主办方或制作方公开材料；平台案例补充表达和体验参考。不要为凑平台数量全网扫库，也不要把投标演示、传播笔记、复盘照片、设计效果图和执行手册混为同种样本。

需要判断最终呈现时按 `source-access-and-login-workflow.md` 分别记录正文、视觉、原生编辑性核验范围。对看过的样本只提炼本次可迁移的信息结构/图文职责/内容颗粒度/操作字段，并说明本项目用途、规模、阶段、资源与样本的差异；不把其页数、文件套数、参数或平台评分复制为统一标准。关键用途找不到足够可见样本时，明确采用本次拟定的交付标准及依据，不能编一个“行业通行”结论来补证。

### 六点一、视觉源路由与可用性

视觉与内容生产如何衔接按[主定义“三、视觉取材接口”“四、生产接口”](research-and-content-production-loop.md)执行；本模块负责定位图源与证明实际可见性。优先寻找主办/运营/品牌、场地或设计/制作方的原发布页、官方图集、平面图及过程视频，写清发布者与页面内位置。媒体和参与者现场图可补充体验与真实状态；搜索缩略图、设计图站摘要只作定位线索，不能直接代表该项目原图。

每个拟采用的视觉材料关联 `source_id/asset_id`，按[访问工作流](source-access-and-login-workflow.md)“四点一、视觉材料的实际读取与取材记录”核验：图片/作品身份、来源性质、拍摄/事件与发布时间、实际看见的页/图/帧、画面观察、借鉴用途及尚未看见部分。原始发布图是来源关系，现场照/效果图/原创示意图是材料性质，分别登记；不能因为图来自官方就认定它是已落地现场。

原页链接、图像可实际打开、已查看画面、已生成可打开的摘图/截图、登录或展示受限分别记录。只有工具确实返回或保存且复核可打开的图像才标“已取得摘图”；未取得就保留原页/图源位置与缺口。不得下载远程媒体绕过展示限制，不得假装已截图、已看图或已核对现场。正文阅读可以继续，但其结论不能代替未完成的视觉核验。

每个来源引用前必须确认：

1. 链接或页面真实存在，不是 404/403。
2. 内容确实支持引用，不是只标题相似。
3. 评论区、热榜、平台数据能否真实看到。
4. 访问方式和访问状态已经记录。
5. 抓不到的，诚实标注“待验证”“需登录”“需账号权限”或“访问受限”。

输出时逐条绑定：

| 事实/信号及问题编号 | source_id、来源名称与链接或用户原话 | 事件/发布/检索日期 | 原文已读位置与访问状态 | 证据等级、置信度与限制 | 支持/改变的判断或内容用途 |
|---|---|---|---|---|---|

禁止只在文末堆来源。

## 七、内部记录格式（按信号强度分层）

检索完，内部按信号强度分层记录；给用户的研究阶段输出摘取最影响判断的信号、依据和待验证项，完整执行记录与原文入口保存可续接：

- **Tier S**：与具体声明相匹配的一手材料或独立交叉证据，实际读取支持该判断；不自动代表效果因果或总体规律。
- **Tier A**：有启发但样本、独立性或访问范围不足的信号，标明限制；只可见标题不能据此验证评论内容。
- **Tier C**：反向信号，用户讨厌、吐槽、抵触或觉得尴尬的点。

Tier S/A/C是既有检索标签，兼含强度与方向；使用时同时保留事实等级、置信度和限制，不能据标签直接断言普遍规律。反向观察也可以有高或低置信度，具体声明按证据规则核验。

内部必须保留主动反证的检索记录。找到相关反向材料时登记 Tier C；未发现或访问受限时保留相应状态及范围，不能为补齐 Tier C 伪造评论。策划提出的失效条件单列为推演，不冒充外部反向信号。

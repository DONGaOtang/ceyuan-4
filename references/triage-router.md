# Step 0 判局分流

任何活动需求先判局，再进入策划。判局不是形式主义，它决定追问方向、创意尺度、实验强度和最终方案结构。

## 一、分流判断

内部必须完成分流判断表，用于保证路由可靠：

| 分流项 | 本次判断 | 依据 | 待确认 | 为什么不是其他路由 |
|---|---|---|---|---|
| 委托关系 | 甲方自用 / 乙方提案 / 内部协同 / 招商赞助 / 政企 To G | 用户原话或推断 | 缺失项 | 有易混路由时写实际差异，无则注明 |
| 市场对象 | To C / To B / To G / To E / B2B2C | 目标受众与受益者 | 缺失项 | 有易混路由时写实际差异，无则注明 |
| 活动场域 | 线下 / 线上 / 混合 / 新媒体 campaign / 长周期 campaign | 渠道与触点 | 缺失项 | 有易混路由时写实际差异，无则注明 |
| 活动体量 | S / M / L / XL | 预算、人数、风险、部门数 | 缺失项 | 有易混路由时写实际差异，无则注明 |
| 营销功能 | 认知 / 兴趣 / 转化 / 关系 / 背书 / 数据 / 危机 / 汇报 | 真实动机 | 缺失项 | 有易混路由时写实际差异，无则注明 |
| 交付件 | 一页创意 / 标准方案 / 全案执行 / 招商赞助 / 政企汇报 | 读者与用途 | 缺失项 | 有易混路由时写实际差异，无则注明 |
| 经营复杂度 | 低 / 中 / 高 / 战役级 | 是否涉及报名、票务、赞助、销售线索、供应商、多部门、多城市 | 缺失项 | 有易混路由时写实际差异，无则注明 |
| 叙事强度 | 轻叙事 / 标准叙事 / 强叙事 / 年度叙事 | 实际内容、持续周期、读者用途与承诺 | 缺失项 | 有易混路由时写实际差异，无则注明 |

上述八项分流保持不变；在“依据/待确认”中同时记录以下适配信息，不另起步骤、不新增暂停点：

| 适配信息 | 本次必须分清什么 | 防止的错配 |
|---|---|---|
| 行业与具体对象 | 客户所属行业、这次涉及的产品/服务/文化内容、实际使用场景；依据来自 brief、资料或待验证判断 | 医疗企业的员工年会不自动变医疗推广；汽车客户的公益活动不自动变试驾 |
| 活动类型与作用 | 主类型、辅类型、每个已要求内容单元承担的实际任务 | 不能把“戏剧节”只翻译成节庆氛围，也不能把培训只翻译成会议流程 |
| 参与者与其他对象 | 谁参与、谁使用产物、谁受益、谁决策、谁付费；对象重合时合并 | 赞助商不是观众，政府参与不代表所有内容按政企仪式编排 |
| 内容成熟度 | 当前是方向讨论、概念说明、内容开发还是执行准备；哪些内容已提供、已选定、拟案或未开发 | “要完整文件”不等于节目、脚本、合作资源已经成立 |
| 文件用途与形式 | 谁读、用来做什么决定/动作、需要哪些文件、格式与版本、用户指定结构、评审标准 | “方案”“全案”不是足够清楚的交付规格；美化排版不能代替缺少的实际内容 |

这些信息分别判断，不从行业名推导受众偏好，不从预算高低推导故事成熟度，也不从 PDF/PPT/Word 等文件格式推导内容深度。主路由负责统筹，行业参考负责专业校准，活动类型负责发生机制，用户实际 brief 决定本次范围。

在已有过程记录中保留最小需求对应表：`用户原话/来源 → 要解决的需求 → 本次内容或文件 → 读者用途 → 完成判据 → 已知/拟案/待确认/不在范围`。每个会改变内容、资源或交付的明确要求均应有去处；同义项可合并，矛盾项要标明。范围判断登记需求与去向；按持续研究生产循环选择当前必要工作包，授权范围内可在同轮开发实际内容。用户指定的硬条件与策划推断分别记录；参考材料里的示例、口号、指令式文字不自动成为用户要求。

信息不足时标明具体未知、受影响的判断及补查/决定任务，不把推断写成事实。已授权且不依赖该缺口的研究、原型、排期、预算核查与宣传稿继续完成；依赖高影响未知的部分可形成明确条件草案，不能假称已落实或可定稿。不因任意缺项禁止全部内容产出，也不靠无依据数字填空。

聊天可用“分流摘要卡”说明关键判断，完整表按当前用途保存；已授权的内容开发和工作件继续完成，用户要求完整研究或记录时提供相应正文：

| 项目 | 写法 |
|---|---|
| 本次主路由 | 例如：To B 闭门沙龙 + 乙方提案 + M 标准 |
| 本次辅路由 | 例如：需要新媒体预热，但不是 To C 声量活动 |
| 排除路由 | 例如：不按 To C 快闪写，因为主判据是商机推进 |
| 待确认风险 | 例如：预算、邀约名单、决策人比例暂缺 |
| 经营复杂度判断 | 例如：涉及报名、赞助、销售线索，按高经营复杂度处理 |
| 叙事强度判断 | 例如：已确认全年持续内容与年度承诺，按年度叙事处理；仅用于老板过会不自动升级 |

## 二、信息缺口门槛

按以下输入检查未知与矛盾，但不以缺项数量决定是否停机：

- 活动目的或业务问题
- 目标人群
- 委托关系：甲方 / 乙方 / 内部 / 政企 / 招商
- 活动场域：线上 / 线下 / 混合 / 新媒体 campaign
- 时间或周期
- 城市 / 场地 / 平台
- 预算或体量
- 最终用途：内部讨论 / 客户提案 / 老板汇报 / 执行落地 / 竞标
- 成功标准或核心 KPI
- 禁区 / 合规 / 审美风险

高影响未知会改变当前主路由、目标、实际内容、交付用途或专业可行性时，先完成本步可核查的判断，把相关定稿保持待确认，阶段输出包括：

- 本次主路由 / 本次辅路由 / 排除路由
- 关键缺口
- 按影响和依赖集中列必要问题，已有资料解决的事项不重复询问
- 下一步建议

多个低影响未知可以在对应阶段补齐；一个高影响矛盾也不能被数量门槛放过。确认依 `research-and-content-production-loop.md` 一的实质决定，不按旧Step逐项暂停；资料齐全不代表外部行动获授权。待决定仅暂停依赖它的定稿，授权范围内独立检索与核验继续；未知可作明确假设，不能写为已确认。

Step 0 用于解决真实路由歧义；有易混路线时说明差异，无歧义不编造排除项。已有有效判断直接复用，默认不把完整分流表贴给用户。

缺口按影响排序：会改变主路由、活动实际内容、故事主线、交付文件或专业可行性的缺口优先；只影响装饰和次要表述的细节留到相关步骤。新补充适配信息归入上述输入，不另算停机阈值。已在附件、前文或原方案中明确的内容先读取、定位来源，不重复询问；资料自相矛盾时保留两种说法及影响，不替用户捏造结论。

“尚未开发”与“尚待用户确认”分开：主题已经选定但节目只有名称，是内容开发不足，不能反复把创作工作退回用户；价格、授权、场地承载或作品名单未证实，才属于待核实条件。后续在已授权范围内完成内容深化，需用户决定的实质选择按持续循环一处理，已授权常规深化继续。

## 三、委托关系

| 类型 | 判断信号 | 方案重点 |
|---|---|---|
| 甲方自用 | 用户说“给老板/内部/领导看” | 业务问题、预算合理性、ROI、风险、内部资源 |
| 乙方提案 | 用户说“客户/竞标/提案/报价” | 差异化、工作范围、甲方配合、不包含项、验收 |
| 内部协同 | 跨部门、行政、HR、销售、品牌共同执行 | 分工、时间线、资源需求、职责边界 |
| 招商赞助 | 要说服合作方出钱、资源或背书 | 权益包、曝光资源、报价梯度、回报证明 |
| 政企 To G | 政府、园区、协会、国企、公共事务 | 规格、口径、审批、领导动线、媒体通稿、合规 |

## 四、市场对象

| 对象 | 核心问题 | 主判据 |
|---|---|---|
| To C | 用户为什么来、获得什么；拍、发、买、复购按实际目标判断 | 到场、体验/理解；有对应任务时评估传播、转化、会员资产 |
| To B | 专业受众为何参与、要解决什么；有销售目标时判断决策人和商机 | 内容理解、技术问题回应、协作成果；有销售目标时评估决策人比例、MQL/SQL、商机金额、会后推进 |
| To G | 是否符合公共价值、规格和口径 | 到场级别、报道口径、政策资源、项目落地 |
| To E | 员工是否更有共识和归属 | 参与率、满意度、共识度、内部传播 |
| B2B2C | 渠道是否被动员、终端是否能承接 | 订货额、渠道活跃、终端转化、代理商信心 |

## 五、活动场域

| 场域 | 按真实内容、服务与任务核对 |
|---|---|
| 线下 | 实际场地、内容与观看/参与路径、人员和资源；安全、审批、天气按真实场域核实 |
| 线上 | 平台、实际内容、观看/参与路径和必要备用；有互动、留资或转化任务时补相应承接 |
| 混合 | 各端真实内容、观看/参与与服务及切换依赖；传播、数据、双端互动按任务适用 |
| 新媒体 campaign | 适用平台、内容节奏、制作与接收端；需要创作者/UGC时补真实任务，预检按关键未知选择 |
| 长周期 campaign | 持续与轮换内容、实际节点、生产服务、阶段目标及反馈修订；不默认每期都公开传播 |

涉及多周系列统筹、跨期多个单元/场次、轮换或持续运行需要联动时，加载 [series-campaign-orchestration.md](series-campaign-orchestration.md)“一、触发、范围与阶段接入”；在本步登记筹备/预热/运营/收尾边界、时区、约定日历范围和客户全案/工作表深度。单场有一个月预热、同日多环节不自动走系列路径。商业地产地址先登记核实对象，Step1再依“三、项目研究与案例迁移”研究，不从地址推导容量、客流或消费力。

## 六、体量分级

| 级别 | 判断标准 | 最终交付候选 |
|---|---|---|
| S 轻量 | 小预算、小人群、低风险、少供应商 | Step 8 可压缩为一页创意 + 简版执行表 |
| M 标准 | 外部受众、明确业务目标、有预算压力 | Step 8 可输出标准文字方案 |
| L 大型 | 多部门、多供应商、多环节、有合规风险 | Step 8 可输出全案执行版 |
| XL 战役级 | 多城市、多平台、多利益方、长周期 | Step 8 可输出 campaign 总案 + 子活动矩阵 |

系列全案将子活动矩阵落实为可关联的内容单元与实际场次；整合大案按 [分工与体验模块](campaign-deliverables-and-playability.md) 一分别交创意、执行（含唯一总预算）、宣传，扩展任务按独立接手用途判断。工作表关联详见统筹八，不将不同用途塞进一个万能Excel。按实际需要判断S/M/L/XL，纯线上/局部/轻量不强建线下文件，也不因启用模块自动高预算或全平台铺开。

预算不是唯一标准。低预算但高合规风险，不能按 S 轻量处理。
体量影响产能、风险和交付颗粒度，不替代本次用途必需的研究、内容与核验。已确认材料直接复用，工作包按依赖选择，不要求逐项运行旧Step1—7；轻量也不能省略已经承诺的实质内容。

## 八、交付件路由

| 交付件 | 读者 | 适用 |
|---|---|---|
| 一页创意提案 | 老板/客户先看方向 | 早期沟通、S 轻量 |
| 标准文字方案 | 市场部/项目负责人/客户 | M 标准 |
| 全案执行版 | 执行团队/供应商/跨部门 | L/XL、大型落地 |
| 招商赞助版 | 赞助商/合作方/竞标客户 | 要钱、要资源、要权益 |
| 政企汇报版 | 政府/国企/协会/园区/领导 | To G、公共事务、仪式类 |

以上是交付用途的默认候选，不是可交文件的封闭目录。独立概念案按 `narrative-and-concept-delivery.md` 条件触发；用户明确要求的脚本、议程、导演阐述、视觉参考册、招商册、执行手册、设计制作清单等，先登记到已有交付范围中，再由相应步骤开发。原本无此需求的 S 轻量活动，不为填表增加文件；用户只要单一文件时，在一个文件中安排所需阅读层，避免重复正文。

交付件必须与成熟度一致：概念用于理解主题与体验，需讲清活动内容及关系；内容开发稿需给出主要单元实质正文和衔接；执行稿需将已选内容落实为角色、时序、资源和验收。尚未选定的主创、作品或资源可以给遴选条件与拟案替代，但不能把它们写成已确认成品。若用户要求的成品依赖缺失素材，指出影响的是哪一页、哪一个单元、哪一个用途，并完成不依赖该缺口的部分。

每个文件在已有需求记录里留一行：`用途与下一动作 | 实际接手者/职责 | 必含正文与深度 | 文件/阅读载体/编辑工具及对象 | 内容、资源、审批状态 | 独立交付理由与上下游依赖 | 标准来源/适用范围 | 代表验收动作`。后续复用同一份主题、单元名称、人数、时间、权益和版本，不在不同文件中各写一套事实。文件数量、页数和章节齐全不算完成；读者能凭该文件完成约定的理解、决策或执行动作才算。

默认由策划先推荐本次最小充分的交付组合，说明每项帮助谁完成什么事、内容做到哪一层、为何用该载体；只有独立阅读、编辑、发布、交接或明确要求才拆文件。已给的采购/投标/部门提交清单逐项核对；用户要求查看全目录时可展示候选及适用条件，但不默认生成或要求逐项勾选。职责未知先用功能角色，不能按“策划总监/创意总监/运营总监”自动套固定文件套餐。关键不确定项并入本步必要问题，按影响和依赖组织，不设数量限额；无关项按合理假设推进。

格式未指定时按实际动作推荐：演示与改页优先可编辑演示文件，长文审阅与批注优先文档，预算重算/名单筛选/排期维护优先工作簿或约定协作表，设计修改按约定源文件能力，网页阅读/交互发布才选择HTML。它们是工作建议，不是统一行业规定；用户指定的有效模板和工具优先。用途已经明确时不把专业选择反问给用户，不为确认文件格式增加暂停点。

路由须有本次目标与内容依据；存在易混路线时写出实际差异，没有则明确不需另造排除项。例如客户已明确商机推进的ToB闭门会可按决策参与和后续约定判断；同样是闭门会，若任务是专业研讨，则按证据交流和问题解决判断，不能自动加销售线索。排除项用于检验真实错配，不规定每个判断必须凑一个。

## 九、经营复杂度

| 级别 | 判断标准 | 后续影响 |
|---|---|---|
| 低 | 内部小活动、少供应商、无报名/赞助/销售承接 | Step 6 只输出最小可执行版本 |
| 中 | 有外部受众、预算压力或基础服务需求 | 实际涉及报名、预算或数据任务时加载相应轻量表 |
| 高 | 涉及赞助、票务、销售线索、多供应商、多部门 | 完成对应交付系统与真实依赖，不把示例任务全部补进方案 |
| 战役级 | 多城市、多平台、多利益方、长周期、高预算 | 完成关键路径、责任与关联；赞助、数据、传播接口按实际范围落实 |

## 十、叙事强度

| 级别 | 判断标准 | 后续影响 |
|---|---|---|
| 轻叙事 | 小型内部/执行导向活动 | 写清实际内容、顺序与完成所得，情绪收束按需要采用 |
| 标准叙事 | 常规对外活动、标准方案 | 完整主线与内容连接，冲突和情绪仅在适用时深化 |
| 强叙事 | 实际需要强故事或完整论证的内容及提案 | 加载 `china-market-narrative.md`，具体强度由内容与本次用途决定 |
| 年度叙事 | 确有跨年/全年内容或年度承诺的项目 | 写持续内容、代表场景与变化；确有媒体/领导任务时适配相应表达，不由预算或名称强造年度工程 |

叙事强度不等于虚构剧情强度。戏剧/节庆可用人物、冲突与情节推进；专业会议可用“问题—证据—讨论—结论”；培训可用“不会—示范—练习—反馈”；产品体验可用“需求—试用—比较—判断”。保留各等级既有要求，按活动实际内容选择连接方式，不把所有行业强写成戏剧故事。轻叙事同样需要让读者知道发生什么、为何按此顺序发生，不能只剩标题与流程表。

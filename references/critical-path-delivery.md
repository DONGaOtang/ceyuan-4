# 关键路径与交付系统

本文件用于 Step 6 交付系统设计、Step 8 全案执行版、Step 9 交付一致性终审。目标是把方案变成可排产、可验收、可压缩的项目系统。

## 一、触发条件

- L/XL 活动、正式提案、跨部门、跨供应商、多场地、多城市。
- 涉及搭建、AV、直播、嘉宾、媒体、政府审批、赞助商履约。
- 用户要求全案执行、落地排期、Run of Show、供应商协同。
- 系列活动需要共享资源、多场次调度或持续内容制作时。

不满足以上条件时，不要把方案写成制片手册。S/M 级创意方案只需要列关键执行假设、关键路径摘要和明显风险；完整 SOP、点位图、call sheet、物料进出场表属于执行交付附件，不是所有策划案的默认正文。

每个任务的完成点须能验收：例如“内容定稿”应对应已完成的单元正文/脚本版本，“设计定稿”对应实际设计文件与规格确认，“嘉宾确认”对应确认记录，不能把发起邀约等同锁定。依赖含事实/资源未确认时标出影响和替代条件，计划完成时间不等于已经完成。内容制作、审核、授权、技术转译和素材交付都计入对应任务的依赖，避免只排搭建和采购。

## 三、T-minus 倒排原则

按活动日倒推，不要只写自然日期。

系列项目先确定全期筹备、预热、运营、收尾边界，再为重点实际场次分别倒排；不能将唯一一个 D-day 扩写成全期执行。内容单元 `unit_id` 与实际场次 `session_id` 沿用 [系列统筹模块](series-campaign-orchestration.md) 的“二、关联对象与变更”：同一单元复演建立多条场次记录，改期保留 `session_id`、原时间与变更记录，取消保留状态。场次可引用一个或多个内容单元，ROS 和脚本关联相应版本。

| 阶段 | 重点 |
|---|---|
| T-60/T-45 | 目标、预算、场地、主叙事、核心供应商 |
| T-30 | 报名/邀约启动、主视觉、嘉宾、传播计划、审批材料 |
| T-14 | 物料下单、Run of Show、人员分工、媒体/嘉宾确认 |
| T-7 | 现场动线、签到名单、提醒、供应商会、应急预案 |
| T-3 | 全流程彩排、物料到位、数据表、话术和主持确认 |
| D-day | 现场执行、异常记录、素材采集、数据回收 |
| T+1/T+3/T+7 | 感谢、线索跟进、复盘数据、传播长尾、财务核对 |

上表为倒排检查示例，T-60、T-45、T+1等不是统一交付窗口；实际起止由审批时限、合同、场地、供应商、素材与接手团队能力确定。任务已完成或本案不适用时直接记录依据，不为套节点重复执行。

|---|---|---|---|---|
| 策略/主叙事 |  |  | 品牌/老板/客户 |  |

岗位可以先拟定，但真实负责人未指定时写“待指派”，不能杜撰姓名或联系方式。跨团队交接写在对应工作流：交什么文件/版本、谁收、何时收、按什么标准确认、退回如何处理；收到文件不等于完成内容/技术验收。

## 五、当天 Run of Show

本次交付包含线下/直播/混合活动的现场调度时，必须准备当天Run of Show；仅做概念或方向评审时，说明关键时序与可行条件，不强制提前完成制作级控台表。聊天按接手需要给摘要或具体表，已形成的完整工作件随本次授权范围保存和核验；进入执行交付时须提供接手者可访问的实际文件，不能仅藏在内部过程或以旧Step编号推迟。

| 时间 | 环节 | 地点 | 用户动作 | 工作人员动作 | AV/物料 | 负责人 | 备用方案 |
|---|---|---|---|---|---|---|---|

当天流程和倒排期不能混在一张表里。

在现有列内写到可操作：环节引用实际内容单元与脚本版本，工作人员动作列写开始/结束或交接信号，AV/物料列写所用素材与 cue；备用方案说明切换条件和决定人。演出、仪式、发布、直播等关键切换按分钟或 cue 细化；不能用小时级总览冒充控台执行单。

执行交付时，ROS 与实际互动规则、主持串词、嘉宾提示、演出脚本、导览讲稿、播控素材等按已约定范围形成可访问的执行附件；小活动中同一接手用途可并入同一文件。未约定完整剧本制作时明确当前脚本深度和后续责任，不把梗概命名为完整剧本。聊天可给摘要，但本次已授权的完整工作件随完成保存和核验，不能以旧Step编号推迟；确认按持续循环的实质决定处理。

## 六、设计制作交接边界

设计物料没有通用固定规格。尺寸、材质、出血、文件格式、安装方式、制作周期、版权授权、打样轮次，取决于场地、供应商、媒介和预算。

触发条件：

- 用户要求可执行全案、供应商 Brief、物料制作或现场搭建。
- 方案包含主视觉、舞台、导视、展陈、印刷、屏幕内容、快闪装置、礼品包装。
- 已知场地、点位、屏幕比例、印刷或制作供应商要求。

触发后必须补齐：

| 物料 | 使用位置 | 尺寸/比例 | 材质/媒介 | 数量 | 交付格式 | 依赖 | 截止时间 | 验收标准 |
|---|---|---|---|---|---|---|---|---|

无法确定规格时，标为“待场地/供应商确认”，不要编造一个看似专业但不可执行的尺寸。

视觉方向图、氛围图、参考图、场地示意图、可制作设计稿分别标注用途与状态。AI 生成的效果图不证明尺寸、承重、功率、消防间距、通行容量和安装可行；这些须由场地勘测、设备参数、供应商资料或合资格专业方确认。未经确认不得声称可施工、可下单、技术已验收；可先给信息需求、使用场景、内容版面、建议比例及待确认规格，继续完成不依赖现场数据的设计内容。

表中“交付格式”应对应真实可用文件及版本；效果图、提示词、源文件、印刷/播控文件不能互相冒充。设计修改若影响内容承诺、镜头、点位、预算或排期，同步相关文件并复核。

## 七、现场制片 SOP 边界

SOP 的作用不是让方案显得更完整，而是减少现场失败：人找不到、物料没到、车进不了、供电不够、网络断、嘉宾迟到、天气变化、责任无人认领。

触发条件：

- L/XL 活动、多供应商、多点位、多城市、直播/舞台/搭建/嘉宾/政府接待。
- 用户明确要求落地执行、现场手册、项目排期或供应商协同。
- 现场失败会造成安全、舆情、客户关系或重大成本损失。

触发后按本案实际场域、风险和交付范围选择所需SOP，进入对应执行工作件或附件，不抢占正式方案主线。下表是检查菜单，实际存在且影响交付的条件必须写清；仅交项目排期不自动附送完整现场手册，纯线上直播不虚造点位、消防、医务、车证或进撤场，须核真实控台、网络、权限、人员联络与故障切换。

| 模块 | 适用时的必要内容 |
|---|---|
| 点位图 | 签到、舞台、互动、展陈、餐饮、仓储、医务、消防通道 |
| Call sheet | 到岗时间、岗位、电话、负责人、替补 |
| 物料进出场 | 物料名、数量、到场时间、负责人、存放点、撤场方式 |
| 供应商通讯录 | 公司、接口人、电话、职责、到撤场时间 |
| 证件车辆 | 人员证件、车证、进场路线、装卸区 |
| 电力网络 | 用电点位、功率、网络需求、备份方案 |
| 应急记录 | 问题、发生时间、处理人、处理方式、复盘归因 |

## 八、压缩时间线原则

时间不足时可以并行，但不能跳过：

- 合规/审批/消防/安全。
- 核心环节彩排。
- 报名和到场确认。
- 主持/嘉宾/销售话术对齐。
- 数据采集表和负责人确认。

以上仅检查本案适用且必要的条件；无报名的开放观看不补造到场确认，无主持/嘉宾/销售的内容不加相应岗位。法定、场地、合同或技术必要条件按其实际要求落实，不能因压缩排期静默删除。

可压缩项：

- 定制物料。
- 大规模搭建。
- 非核心传播物料。
- 低价值礼品。
- 复杂互动支线。

## 八点五、系列资源与制作产能

系列模式另读 [系列统筹模块](series-campaign-orchestration.md) 的“六、资源、产能与预算”“八、执行工作簿接口”“九、联动验收”。资源表管理可用性与占用，预算表管理成本，不能拿已列费用证明资源已锁定。

为实际共享的场地、装置、舞台、设备、人员或服务池建立稳定 `resource_id`，按相关 `session_id` 或 `asset_id` 登记占用起止、搭拆/转场/运输缓冲、需用数量、已核实的池容量、负责人及确认状态。持续装置按全期占用登记；复演可复用资产，但实际场次和占用分别保留。未知池容量标待场地/供应商确认，不用虚构容量排出可执行结论。

同一资源在交叠占用窗口内的需用量不得超过已确认可用量；人名不同或改了场次标题不能掩盖同一套舞台、同一个团队的冲突。摄影、剪辑、设计、授权和审核按实际输入、处理能力、完成时间及下一步截止同步排期，未核实产能只作待验证假设。重点传播素材的截止必须晚于取得/授权时间，并留出约定审核与修改时间；用模板复用也要计入变体制作和校核工作。

改期、取消、资源替换或制作延迟时，沿原 `session_id` 检查邀请与用户通知、已发/待发预告、素材交接、点位占用、搭拆转场、预算和商户权益，记录变更责任和尚未闭合项。执行者必须能够定位受影响记录；计划表写了新日期但旧传播仍在发布，视为关联未同步。

## 八点六、热度突增与接待状态联动（主定义）

当传播、招募或突发变化可能让需求超过可兑现能力时，由执行维护现有场次/点位记录中的接待状态、依据及截至时间；报名、宣传、商户和服务团队引用同一状态，不另建容量主值。可以使用人工状态记录和明确通知责任，不默认购买实时系统。场地总容量、体验点位容量、预约库存、排队处理速度和人员服务能力分别确认；未知值标待核，某个体验满额不代表整个项目停止接待。

项目按实际需要采用正常、接近已确认限制、满额/服务中断、恢复等状态。触发条件来自已确认容量、预约/排队和服务记录，不设通用满额百分比。记录受影响点位/session_id、状态及证据、切换决定人、各接收负责人、有效时段、尚未通知项、替代与恢复条件。

| 状态变化 | 必须完成的适用交接 |
|---|---|
| 接近限制 | 核查预约与排队是否重复计数，确认真实剩余承接能力；准备收紧招募、候补或延后指引，宣传同步当前条件 |
| 满额或中断 | 更新报名/候补入口、规则页、置顶与现场话术；通知承担相关招募的创作者及客服，暂停失实的“直接来/一定可参加”承诺；已出发、已到场、已预约者分别提供当前可兑现处理 |
| 可用替代 | 写明替代内容、地点/时段、容量和负责接收者及资源依据；可继续开放的其他区域说明真实服务范围，不承诺未经落实的加场、补偿或优先权 |
| 恢复 | 负责人确认资源/服务已恢复、入口与规则更新、接手岗位收到信息后，记录恢复依据与时间；按metrics-flow八决定相关招募/投入是否恢复，不能只凭热度回落解除限制 |

执行交付前，对关键高需求单元做适用的联合走读：以“创作者内容突然放大、目标体验已满、其他区域仍开放”为情境，查当前状态从谁传到报名、宣传、现场和商户，检查每处实际待发说明及可兑现替代；没有真实流量和现场条件时标桌面演练。发布或通知草案与实际已发送状态分开，外部动作按已有授权执行。容量与成本有变化时同步相关资源和唯一预算，不由宣传自行增加场次。

## 九、交付一致性检查

交付与修订时检查本次适用及受影响项；旧Step9是能力索引，不新增统一阶段或完整表配额：

| 检查项 | 规则 |
|---|---|
| 人数 | 邀约数、报名数、到场数、场地容量、餐饮数一致 |
| 时间 | 审批、设计、制作、搭建、彩排能按依赖完成 |
| 预算 | 分项、总额、应急金、不可砍项一致 |
| 权益 | 赞助承诺有现场资源和传播资源支撑 |
| 数据 | KPI 有采集点、负责人和工具 |
| 销售 | 有销售任务时核对适用识别、评级、跟进与CRM；无销售任务承接已约定资料/问题回应，不强造线索 |
| 内容 | 单元名称/编号、故事/议题内容、场次版本、时长和前后关系在正文、概念案、ROS、脚本及视觉中一致 |
| 资源状态 | 拟议、已确认、待采购、已到位分别有依据；概念可读不等于现场可执行 |
| 文件 | 用户要求的真实文件和附件已生成、可读取、可定位，源稿与导出版本一致；未交或未核验明确列出 |
| 接手 | 执行者能从交接材料识别动作、输入、完成条件与异常处理，不必根据口号重新创作 |
| 系列关联 | 同一单元复演与实际场次可区分；邀请、日历、资源、费用和测量能追溯到对应对象，改期/取消有记录并完成影响核对 |
| 资源与产能 | 占用起止含实际搭拆转场缓冲；共享池无超容量占用，素材取得、剪辑、授权、审核与发布依赖能够成立 |
| 全期成本 | 共用 `cost_id` 在成本主账计一次，分摊仅作解释；改期取消的实际费用与可退费用有明确口径 |
| 接待联动 | 关键点位的限制、替代、报名/宣传/现场信息和恢复责任可以对照实际版本；暂停招募不被误记为全项目关闭或合同取消 |

“一致”指口径和数量关系能解释，不要求邀约、报名、到场、容量、餐饮数机械相等；须分别注明人数定义、漏斗关系、上限和预留。预算总额遵守分项小计加应急金的统一口径，不重复计提。追踪记录按 `proposal-schema.md`，关键失败未闭合不得以高分判可上交。

系列项目区分邀约池、报名人数、预计/实际到场、同时在场容量、累计参与人次与可识别的去重人数；跨场人数不能直接加成去重人数。对应定义与开放街区测量边界沿用 `registration-and-attendance.md`。执行工作表按 [分工规则](campaign-deliverables-and-playability.md) 一、四归入同一执行用途的工作簿，详细ROS/脚本按实际接手需要索引。完整创意与宣传日历独立维护，执行只引用内容版本、采集/制作/审核占用和费用；不默认拆空附件或合并不相干用途。

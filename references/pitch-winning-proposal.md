# 中标型正式提案增强

本文件用于需要采购说服、资源取舍或决策表达的提案任务。预算、客户或行业标签不自动增加整套中标正文；局部更新与已选方向仅补本次需要的判断内容。

## 一、触发条件

命中任一条即触发：

- 用户需要解释预算价值、报价取舍、压价影响或较复杂的投资决定，不用固定金额划分所有行业项目。
- 用户要给甲方、老板、领导、评审会、比稿会、采购会看。
- 项目需要成为年度事件、城市事件、品牌事件、节庆主线或传播战役。
- 多个内容或服务单元的关系、价值和资源取舍不清，容易被看成零散服务清单。
- 传播由外部公司、媒体公司、达人/KOL 团队或甲方传播部门承接。

若触发原因是文旅、艺术文化、海边社区或阿那亚类项目，必须先按 `culture-tourism-boundary.md` 确认场景命中，再叠加 `culture-tourism-strong-narrative.md`。高预算或老板过会本身不等于文旅强叙事。

## 二、中标型提案五个硬门禁

正式成案前按本次用途逐项回答。发现缺口时说明对提案判断的影响及具体修法，不因基础目录齐全就默认可上交。

该判定只评价中标表达，并以 brief 实质覆盖、内容可理解、关键事实可信、文件真实可用等基础交付验收已通过为前提；基础项失败仍不得上交。“看起来有中标力”不能替代用户要的活动内容、实际文件或执行依据。

| 门禁 | 必须产出 | 不合格表现 |
|---|---|---|
| 强问题定义 | 开篇让决策者看清有依据的问题与本案要实现的变化 | 只写背景、趋势、调性，没有判断依据 |
| 项目可识别价值 | 决策者能复述本案关键内容及项目关系；集中主事件或持续体验按任务选择 | 只记明星、装饰或口号，不能说明活动价值 |
| 模块关系与取舍 | 说明各单元的贡献、依赖与资源配置；可有主次，也可有真实并列关系 | 资源取舍无依据，模块之间关系不明 |
| 预算价值架构 | 按本项目目标解释费用购买的内容、服务和保障，引用唯一明细主账 | 只列费用，无法判断投入与承诺的关系 |
| 传播协同接口 | 有传播交接任务时，按实际节点提供稿件、素材状态、规格、数量依据、责任与接收端 | 只写平台矩阵，或把待采素材当已交成品 |

## 三、强问题定义

开篇给出可核实的问题判断；已有问题定义准确时直接接续，不为提案锐度强行推翻客户需求。

格式：

```
本次需要解决____，依据是____。
方案通过____内容与____服务，帮助____获得____。
当前关键条件是____，据此选择____。
```

要求：

- 在决策者需要作判断的位置清楚表达，不设统一页码或篇幅。
- 要回应客户的真实压力：争议、预算、增长、口碑、审美、组织协同、老板认可。
- 不要为了锋利而冒犯客户。锋利指问题定义准确，不是措辞刺耳。

## 四、项目可识别价值

按目标、受众与内容结构选择集中主事件、多个相互支持的重点场次、持续体验或其他适用结构。高预算和年度标签本身不能推出必须有一个峰值事件；确需集中节点时才用以下说明，持续结构则说明稳定内容、真实变化与再次关注理由。

输出格式：

| 字段 | 写法 |
|---|---|
| 内容名称 | 能被目标读者准确复述并指向实际内容，不设统一字数 |
| 发生时间 | 开幕 / 高峰日 / 闭幕 / 每日固定时刻 |
| 发生地点 | 具体到点位、线路或空间类型 |
| 现场动作 | 谁在何时做什么，观众看见什么 |
| 传播画面 | 一句话描述短视频/照片第一眼 |
| 预算支撑 | 引用执行主账中的费用及其用途，说明取消或降级会损失什么 |
| 风险降级 | 天气、人流、审批、演员、舆情出问题时怎么降级 |

判定标准：目标决策者在实际审阅条件下能否讲清项目独特内容及其价值，必要解释是否清晰。带到访目标时按 `creative-director-quality-bar.md`“项目与地点记忆”检查实际传播组合；提案可复述不代表市场已经记住。

## 五、模块主次关系

内容或资源关系不清时，按实际贡献与依赖说明。以下是可选分类，不按模块数量强制分层，不强造口碑出口或峰值：

| 层级 | 定义 | 预算原则 |
|---|---|---|
| 核心内容 | 直接承载本次已确认目标和受众所得 | 按承诺与替代条件判断取舍 |
| 体验支撑模块 | 帮用户进入、理解、移动、参与 | 可降规格，不可断链 |
| 后续内容与服务 | 确有需求时承接传播、关系、复盘或内容复用 | 按实际任务和资源决定保留与调整 |

每个采用模块说明服务的体验或任务、预期贡献、依赖及取舍影响；指标引用现有适用定义，不为每个内容单元另造量化指标。

资源分层不能代替内容串联。每个模块还要让读者理解实际发生的内容、进入与完成方式、对主问题的贡献及前后/并行关系；活动故事、节目介绍、论坛问题链、展陈导览按活动类型采用合适表达，不用统一营销口号覆盖差异。不能因模块不直接成交就删除文化体验、关系维护或公共价值的已确认要求。

## 六、预算价值架构

按客户的判断需要解释预算购买的内容与服务，再引用明细；不因预算大小强制套同一系统结构。下表仅为可能的归类，选择适用项并改为本案内容，不能成为另一份独立预算。

格式：

| 可选归类 | 包含模块示例 | 解决的问题 | 引用预算占比 | 可观察方向（非效果证明） |
|---|---|---|---|---|
| 进入系统 | 入口、导读、地图、动线、邀约 | 用户如何进入体验 |  | 到场质量、投诉下降、理解成本下降 |
| 发生系统 | 峰值事件、现场动作、仪式、互动 | 为什么必须到现场 |  | 参与率、现场停留、社交传播 |
| 资产系统 | 影像、音频、UGC、KOL、档案、复盘 | 活动结束后留下什么 |  | 内容数量、可复用素材、舆情证据 |
| 保障系统 | 项目管理、人员、合规、应急 | 怎么保证不翻车 |  | 准时交付、事故率、应急记录 |

报价解释必须回答：

- 这笔钱购买的具体内容、服务或必要物料，以及它与承诺的关系。
- 哪些钱花在「可见体验」，哪些钱花在「不可见保障」。
- 哪些是不可砍项，砍掉会影响哪层指标。
- 哪些是可降级项，降级后损失什么。

## 七、传播外包接口

只写平台矩阵不够。正式提案要给传播方可接的素材接口。

交接主定义沿 `new-media-campaign.md`“四点五、传播外包接口”：按已选节点、内容供给、合同和制作能力确定交付对象、数量、规格、来源、成熟度、截止、责任人、接收方及验收条件，不复制固定日更数量或统一交付窗口。提案引用实际Brief、代表稿与服务入口，让接手方知道能拿到什么、哪些仍待采集；规划素材表不等于已生成素材。用户要成品包时核对实际文件、内容与版本，用户只要传播规划时明确后续制作责任。

## 八、系列提案联动

系列项目按 [系列事件统筹](series-campaign-orchestration.md) 一、八、九及 [分工规则](campaign-deliverables-and-playability.md) 一、四、五接入现有成案与终审。项目研究支持判断，创意解释母题/活动内容/体验如何持续，宣传解释线上参与与节点接力，执行解释兑现、资源和唯一预算；效果依据与未知项按指定测量位置引用。相关细表仅在同一接手用途内成工作簿，不把不同职责全塞进客户总案或执行Excel。必要概览引用三个工作件，不再复制完整正文。

传播接口在既有素材交接表之外承接逐日信息主张、目标人群、素材来源、发布账号、行动入口和负责人；日期全覆盖不等于每个平台每天发。邀请资源按任务和匹配依据比较，拟邀、报价、档期核验与已确认分别标注。共享搭建、月度达人包等费用只计一次，分摊说明不能形成重复计费。改期或取消时从实际场次追踪邀请、传播、权益、资源、预算和用户通知的连带变化。

## 九、终审辅助评分

需要比较提案方向或解释表达短板时，可围绕本案采购标准比较问题判断、内容识别、资源取舍、预算价值、适用传播及执行可信度；也可直接作有据的定性比较。采用评分时，在看结果前记录所选维度、尺度、权重及项目依据，并记录证据与置信度，不沿用统一百分制或固定权重。

评分仅用于本次适用维度的比较，不设分数放行线，也不证明实际中标或传播效果。Step 9 以需求内容、证据、数值、关联及执行条件满足本次用途作判定；遗漏已确认核心需求、主要内容空心、系列断裂、资源状态造假、指定文件未交或关键执行条件不满足时，必须修复。判「小修后上交」须列出具体修改、对应文件位置、责任与验收条件，完成后复核才可提交；关键模块不成立则明确重做理由，不能由总分自动推导判词。

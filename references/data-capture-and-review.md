# 数据采集与复盘

本文件用于 Step 3 经营模型、Step 6 交付系统、Step 8 效果评估、Step 9 交付一致性审查。目标是活动前就设计好怎么证明，而不是活动后凭感觉复盘。

## 一、数据采集计划

每个 KPI 必须对应采集点：

下表时间和工具是采集设计示例，按本项目数据形成时间、访问权限、团队能力和约定窗口替换；不将每日、T+1/T+3等作为统一交付时限。局部任务只维护受影响的指标和记录。

| 指标 | 采集点 | 工具/系统 | 负责人 | 采集时间 | 数据口径 | 失败备份 |
|---|---|---|---|---|---|---|
| 报名数 | 报名表后台 | 小程序/表单/票务平台 |  | 每日 | 去重后报名人数 | 手工导出 |
| 到场率 | 签到 | 签到系统/纸质表 |  | D-day | 到场/报名 | 离线名单 |
| 互动率 | 现场任务 | 二维码/互动卡 |  | D-day | 完成互动人数/到场 | 人工计数 |
| 线索质量 | 销售跟进 | CRM |  | T+1/T+3 | A/B/C 或 MQL/SQL | 销售表格 |
| 内容资产 | 素材库 | 网盘/相册/剪辑表 |  | D-day/T+1 | 可用素材数 | 摄影清单 |
| 满意度 | 问卷/访谈 | 问卷星/飞书/电话 |  | T+1/T+3 | 有效样本数 | 1v1 访谈 |

## 二、口径规则

- 报名数按已说明的识别方法去重；无法去重时保留报名记录数及限制。
- 预约场次到场率 = 可匹配有效报名的实际到场人数 / 有效报名人数；散客到场单列，不混入分子。
- 线索要区分 MQL、SQL、Nurture。
- 曝光量区分自然、投放、媒体、达人并记录平台口径；付费达人等分类可能重叠，要先明确分组和重复，再汇总。
- UGC 要区分发布数、有效内容数、可复用授权数。
- 赞助数据要区分全场数据和单赞助商权益数据。

对开放街区、随机进入、无报名活动，采用适用的人次/在场快照/抽样观察，不虚构报名分母或去重能力。所有指标标单位、时间窗、去重方式、分母、样本范围和缺失区间；自然/投放曝光跨平台不得假称去重人数，同一内容的多尺寸导出不算多条原创。

内容效果可用无提示复述、任务完成或真实访谈检验，须保存题目和原始记录；内部模拟、主办方意见和受众真实反馈分开。只有宣传素材不足以证明文化理解、满意度或增量客流。

项目与地点记忆预检使用实际传播组合，记录受众看过哪些素材、在不提示下记住的人物/活动/项目/地点、理解的体验与参与条件、能否找到下一步，以及原话和误解。方法与样本条件按 [实验验证](experiment-validation.md) 三、五选择；内部桌面走读只能指出缺口。可识别时同时标首次接触、已看未到、已参与或复访阶段，不从无法去重的互动量推算个人累计曝光或疲劳。

### 系列项目的核心计数口径（主定义）

系列项目先选择实际能采集的指标，再按 [统筹模块](series-campaign-orchestration.md)“七、测量与每周调整”“八、执行工作簿接口”绑定；不能为填满全案发明去重和归因能力。

| 对象 | 定义与合计规则 |
|---|---|
| 曝光/播放 | 平台记录的展示或播放次数，二者按原口径分列；跨平台相加须注明重复，不能叫去重触达人数 |
| 去重触达 | 特定平台/数据范围内按其识别方法去重的账号或设备数；不自动等于自然人，跨平台无可匹配识别依据不得合成全网去重数 |
| 有效兴趣 | 采用预先约定且可观测的行为，例如规则页有效访问、咨询或收藏；分别记录行为及分母，不把点赞一概当到访意向 |
| 邀约池/发出邀约 | 候选可联系对象与实际发出邀约分别记录；重复邀约动作是次数，不能虚增受邀人数 |
| 报名 | 有效报名记录、可识别去重人数分别记录，按场次保存有效/取消等状态；跨场报名相加为报名人次 |
| 预计到场 | 基于可解释参数的预测；与实际到场、容量分列，不能用预计值回填实绩 |
| 同时在场容量 | 该点位/场次经适用责任方确认的同时接待限制；不同场次容量之和不表示全期客流能力 |
| 累计到访/参与人次 | 每次符合计数规则的到访或参与计一次，注明重复进出和跨单元处理；开放区域的计数/抽样估计与签到实数分开 |
| 可识别的去重人数 | 在明示范围内用稳定可匹配标识识别的人数，说明覆盖率、去重方法和漏识别；未识别参与者不能假定都是新访客 |
| 复访 | 已识别者在约定时窗内完成后续到访；次数与人数分列，分母使用符合相同识别范围的可识别到访者，不代表所有访客 |
| 核销/归因核销 | 按事先说明的有效核销、去重、渠道规则和归因窗口计数；多触点分配明确，累计同一核销不能重复计入总量 |
| 增量 | 相对适用反事实的差额，需记录基线/比较组、时窗、假设及其他解释；无法建立可信比较时只报告观察到的变化或归因结果 |

商业地产入口计数可能包含普通消费、路过与工作人员。项目全场客流、活动点位人次、实际参与者分别采集；统计边界不一致时不能彼此替代。回填样本覆盖、缺失时段和抽样误差说明，不能把照片中出现的人数外推成全天客流。

### 系列采集与工作表关联

研究索引与案例证据用 `source_id` 关联；每个测量项使用 `metric_id`，按适用范围关联 `unit_id`、`session_id`、`asset_id`。全期指标明确标全期，不随意绑定到单场。改期沿用原 `session_id`，记录时间版本；取消场次保留取消状态和已发生数据，取消后的未发生时窗不填成零实绩。

工作簿的测量与每周调整表按用途保留以下字段，详细定义引用本节，不在各表另创口径：

| 记录 | 最低需要的信息 |
|---|---|
| 测量计划 | 指标 ID 与名称、对象关联、单位/分母/时间窗/去重方法、采集点与工具、负责人、采集成本或资源、失败备份 |
| 目标与预测 | 目标或预测类型、基线、参数来源、公式、情景假设、版本、置信度、缺口与预计补充时间 |
| 实际采集 | 数据截至时间、原始材料或后台记录链接、原始值/清洗后的值、覆盖范围、缺失项、修订原因；没有数据保持未取得 |
| 周度调整与异常决定 | 原目标/预测与实际、差异解释及反证、继续/调整/暂停/恢复的对象与依据、观察窗口、负责人/授权及恢复条件；引用受影响场次/资产/资源和cost_id，不复制主账；主定义见metrics-flow八 |

每日采集节奏依实际工具、运营和成本确定，和内容发布频率分开。主办方无法取得某平台去重数据时，保留可得次数与访问限制，不能用行业比例补算去重人数。实绩核验与声明强度继续按 [证据规则](anti-hallucination-and-evidence.md)执行；计算与调整路径见 [指标模型](metrics-flow.md)“六、系列项目的目标与预测”“七、真实数据取得后的每周调整”。

## 三、采集失败备份

每个关键数据都要有 B 方案：

| 失败 | 备份 |
|---|---|
| 签到系统崩 | 纸质名单 + 手工录入 |
| 问卷回收少 | 重点用户 1v1 访谈 |
| CRM 不配合 | 临时线索表 + 销售负责人签字 |
| 社媒数据拿不到 | 截图留证 + 链接归档 |
| 现场互动漏统计 | 抽样计数 + 摄影记录 |

备份只保留其实际支持的证据：截图与链接记录可见数值，不能补出未取得后台指标；访谈可解释体验，不替代原问卷的总体比例；抽样与摄影须注明覆盖、方法和限制，不能外推全场或全天人数。备份同样不可取得时记录缺失及影响，不为补表制造值。

## 四、复盘结构

活动后依据已取得资料回填，数据未提供则交清楚标记的复盘模板和缺口，不填写虚构实绩；报告区分已完成交付、效果结果、不可归因部分与失败：

| 模块 | 问题 |
|---|---|
| 目标 vs 实际 | 主判据赢了吗 |
| 作用路径断点 | 已采用路径上观察到什么缺口，原因是否仍待验证 |
| 实验结论 | 哪个假设被验证/推翻 |
| 叙事表现 | 主叙事是否被复述，主场面是否传播 |
| 执行表现 | 关键路径哪里延误，供应商哪里失控 |
| 数据质量 | 哪些数据没采到，为什么 |
| 下次动作 | 条件复用、当前条件下暂不采用、重测、改目标、改机制；记录适用范围 |

## 五、复盘会议

系列真实反馈的回接按 [持续循环](research-and-content-production-loop.md) 五：已取得观察与待验证原因分开，形成具体补证任务、内容/服务改动、对应稿件或素材版本、负责人/截止与下一次核验。素材缺供、入口异常、权益或资源变化可以即时触发，不只等周会或收尾；无实绩时仅做明示桌面情景，不称已验证运营效果。

复盘时点按数据可得性、调整窗口和负责人能力约定，不固定活动后若干天；系列运营中的周度复核、场次后检查和异常即时处理相互补充，结束后全期复盘另行安排，复访等长线指标按其约定窗口继续跟进。会议议题按本次问题取舍，可按以下顺序组织：

1. 先看主判据，不先讲感受。
2. 再看行为改变是否发生。
3. 再看叙事是否被复述。
4. 再看执行和预算偏差。
5. 最后决定在什么条件下复用、暂不采用或重测。

## 六、条件性复盘与长闭环写回（主定义）

活动结束后，把以下字段写回 `output/` 下的独立沉淀目录或用户指定复盘文档，不得直接写回 `references/` 方法文件：

- 活动类型和推导路径。
- 主叙事和创意机制。
- 目标 vs 实际。
- 断点层。
- 翻车点。
- 实验结论。
- 有条件可复用的动作。
- 当前条件下暂不采用的动作及重查条件。

上述记录按其决策用途展开，不为普通工作备注强建知识库。准备供后续项目引用的结论，须同时留下：实际人群和参与阶段、内容/版本、时间与环境、资源与成本（引用主账）、履约和测量条件、证据类型与强度、样本/缺失范围、其他解释与反证、适用边界、失效或重新核验触发，以及下次最小核查动作。内容是拟案、执行记录还是效果证据分别标注；单次失败只能支持当前条件下的采用判断，不能自动变成永久禁用。

复盘还检查系列内的代价：局部热点是否挤占后续制作、接待或商户服务，是否消耗全期预算、导致下一轮素材不足，取得的素材和关系是否可继续使用。没有相应记录时保留待验证影响，不凭忙碌或热闹断定全期收益。

验收时，让未参加原项目的人依据记录说明“什么条件下可用、不能证明什么、哪些资源必须重新确认”。若会把相关性当增量、旧报价/档期当本期确认、单次失败当长期无效，则补齐条件后再入可复用案例索引。具体继续/调整/暂停/恢复沿用 [运营决定](metrics-flow.md) 八；方法升级仍须人工审查，不因一次复盘自动修改规则。

默认写入位置：

| 目录 | 内容 |
|---|---|
| `output/case-library/` | 成功/失败案例、创意机制、带适用条件的复用与暂不采用结论 |
| `output/run-reviews/` | 跑测记录、验证偏差、调用失败、流程断点 |
| `output/user-projects/` | 用户项目阶段稿、过程输出、最终交付源稿 |
| `output/improvement-log/` | 需要人工审核后才可能升级为方法论的改进建议 |

只有经过人工审核的稳定规律，才允许从 `output/` 升级进 `references/`。

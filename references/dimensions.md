# 需求维度完整性清单（防角度缺失）

供目标和内容判断时按需加载，旧Step2/5为能力索引。核心一句话：**动机解释为什么办，还需核对办什么、为谁办和要取得什么；这些检查角度不能保证穷尽真实需求。**

## 一、三个拆解轴

动机分析回答「为什么」，还需核对本次内容、对象与成果。以下三轴用于检查当前需求，按任务选适用项；单项更新复用已确认判断，不要求每轮重新枚举全部可能性。

### 轴 1 · 目的维度（七状态，要达成什么）

一场活动往往同时背着多类目的，别默认只有「卖货」。目的按 `references/axes.md` 的**七状态**枚举：

- **认知**（让人知道/记住/相信）· **情感**（让人喜欢/认同/归属）· **行为**（让人买/签/来/参与）
- **关系**（拉近/结盟/信任）· **资源**（要钱/要渠道/要人/要数据）
- **身份**（有依据的资格/身份表达）· **生理能力**（身体技能练习、运动或急救操作等适用目标）

> 身份表达和身体技能值得单独核对，但七状态并不互斥。仪式表达不能创造未成立资格，体检信息不等于身体能力已改变，培训也可能以专业理解或行为练习为目标；依据实际内容与所需改变定位，不从名称强行归类。

### 轴 2 · 利益相关方维度（谁要什么，分两层）

每个相关方要的东西不一样，且可能互相冲突。按 `axes.md` 的两层对象拆：

- **参与者**（谁来现场）：消费者 / 员工 / 媒体 / 领导 / 公众
- **受益者**（谁最终获益）：与参与者可能重合、部分交叉或分离；按 `axes.md` 逐案判断实际关系，不从公益/环保/CSR标签断定分离。

各方诉求要单列，且可能冲突：

- **主办方**要什么 · **受众/参与者**要什么 · **参与方**（品牌/商家/媒体/KOL/供应商）要什么 · **监管**要什么（报批/合规/舆情安全）

**硬规则**：把「哪个诉求和哪个诉求打架」标出来（例如主办方要转化、受众只想白嫖体验、媒体要新闻点——三者可能冲突）。冲突点送 Step 7 对抗，别当没看见。

### 轴 3 · 功能维度（这场活动能同时承担什么 = 覆盖几个状态）

活动可能承载多种功能，也可能有明确的单一任务。下表用于检查相关目标，不以覆盖状态数量衡量质量；以促销为唯一任务并不天然有问题，缺少brief明确要求的其他价值才构成遗漏。以下假设性商场示例可帮助定位：

| 功能 | 对应七状态 | 典型承载 |
|---|---|---|
| 商业转化 | 行为 | 促销、招商、逼单 |
| 品牌演绎 | 认知 + 情感 | 发布会、主题展、沉浸体验 |
| 内容传播 | 认知 | 打卡点、挑战赛、话题 |
| 关系经营 | 关系 | 私享会、答谢会、酒会 |
| 体验创新 | 情感 | 峰值时刻、黑科技互动 |
| 数据资产 | 资源 | 留资、私域沉淀、UGC |

**关键**：显眼功能不自动等于唯一功能。若brief还要求品牌、体验或内容价值，不能因为商业转化容易测量而丢掉这些目标；不要求所有商场活动同时承担表中全部功能。

## 二、完整性检查（目标、内容开发与修订时按需使用）

1. **核对**：在本次涉及的目标、对象与功能上检查重要遗漏，保留框架外的实际需求；已有明确判断可引用，局部修订只检查受影响部分，不要求每轮列全所有可能维度。
2. **确认**：依据已确认目标选本次适用维度；确有相互冲突且需要用户决定的取舍时给具体选项，按持续循环一确认。未确认的维度只作明确假设的条件原型，不作已确认承诺；确认的必须有对应创意承载。本文件不得新增独立暂停点。
3. **映射**：实际内容说明服务于哪个已确认目标、受众所得或必要履约条件。有适用目标但无内容承载是缺口；内容无法归入现有维度时先检查它的实际价值和约束，不因标签缺失直接判多余。

## 三、奥莱反例（为什么要这个检查）

- 奥莱商场做活动，方案全聚焦「促销折扣」——因为「商业转化」是它最显眼、最好量化的维度，于是它成了唯一维度。
- 但「整体演绎」= 品牌演绎 + 体验创新 + 内容传播，被一个维度挤掉了。
- 根因：**没有完整性检查，一旦识别出一个显眼维度，就顺着它一条路走到黑。**
- 教训：显眼维度不自动等于唯一维度。目标判断时核对「除了最显眼这个，还有没有用户已明确需要的价值」；已能从资料确认时不重复追问，局部修订沿已有判断。

上述奥莱段落是问题示例，不是已核实客户案例或所有商场的通病。多维检查沿用核对—确认—映射，不把所有可能维度都塞进活动；同时检查用户明确提出的内容、体验和文件，未被七状态命名覆盖的要求也不能消失。

## 四、硬规则

1. **创意有目标依据**：以已确认维度开发；未知维度留明确假设、补证与影响，可继续条件原型和独立研究。需要改变已确认目标的取舍按持续循环一处理，不以旧Step前置确认阻断全部发散。
2. **勾选的维度必须落到具体创意/环节**，不允许「覆盖了但没承载」。
3. **维度冲突要显式标出**（如商业转化 vs 品牌演绎），送 Step 7 对抗审查，别装和谐。

# 对抗审查规则集

供 Step 7 使用。目标不是挑刺，是找「一戳破、整个结构就塌」的根本缺陷。本流程的对抗审查同时攻击策略风险和交付矛盾。

## 一、Steelman 先行（防稻草人）

持续工作按 [研究生产循环](research-and-content-production-loop.md) 五、六挂在本轮重大判断/内容/交付上：核证据独立性和图像误读，攻击真实原料、采集/制作/审核产能、备用、接收端和更新承诺。新反馈要形成具体补证与修稿/修服务，再回读修后版本；局部更新聚焦新增/变化风险，不因旧Step7逐项暂停或每轮复查无关模块。

审查前，先把自己方案说到最强版本——说到「拥护者会点头说：对，这就是我的方案」。再攻击这个最强版。

**禁止**：攻击一个弱化版/曲解版，然后宣布自己赢了。那是自嗨，不是审查。

**检验**：反证打出来后，方案提出者能不能说「这不是我的意思」？能说，说明你打了稻草人。

## 二、攻击角度清单（15 个）

完整大案覆盖下列适用视角；局部或持续更新按当前变化和关键失败条件选择，不强制重复全部清单。**每条反证必须标注依据**：是事实（引用户口碑/数据）还是推测，推测必须标「待验证」，不许凭直觉口嗨。

| # | 攻击视角 | 攻击话术 |
|---|---|---|
| 1 | 凭什么来 | 受众有非来不可的理由吗？ |
| 2 | 传播不出去 | 有值得截图转发的点吗？社交货币在哪？ |
| 3 | 预算错配 | 钱花在了不产生结果的地方吗？ |
| 4 | 执行翻车 | 天气/供应商/现场事故，哪个环节会崩？ |
| 5 | 合规风险 | 报批、消防、食品酒类、广告法、版权，漏了吗？ |
| 6 | 效果难衡量 | 热闹完能归因到结果吗？还是自嗨一场？ |
| 7 | 动机错配 | 这活动满足的是真需求，还是假象？ |
| 8 | 创意自嗨 | 甲方觉得好，受众无感，怎么办？ |
| 9 | 时机错配 | 时间窗口差吗？跟竞品扎堆了吗？ |
| 10 | 资源错配 | 人力/物料/时间够吗？谁来做？ |
| 11 | 假设不成立 | 哪些 Soft/Assumption 被当成了 Hard？ |
| 12 | 二阶效应 | 会不会引发负面舆论、后续麻烦？ |
| 13 | 前提不成立（判死唯一出口） | 这个活动本身一定要办吗？不办活动能不能达成目标？有依据地命中 → 给出不建议办原活动的理由及符合真实目标的具体替代选项；改变已确认方向的决定由用户作出，仅暂停依赖该决定的定稿，独立研究继续。原活动记“需重做关键模块”并保留前提不成立的说明，不把替代方向或多数赞成误记成原活动可上交 |
| 14 | 维度冲突 / 缺失 | 确认的维度全被承载了吗？有没有显眼维度挤掉了其他维度（如促销挤掉品牌演绎）？维度之间打架了吗？ |
| 15 | 推导路径定位错 | 推导路径（七状态→对象→形态→时空）定位对了吗？「这个活动真的是身份确认，还是其实想卖货（行为）」？类型定位错了，方案全错。 |

## 三、V2 交付一致性攻击

策略攻击之后，必须追加交付攻击。正式、大型、To B、赞助、政企、文旅、老板过会项目不能跳过。

| # | 攻击视角 | 攻击话术 |
|---|---|---|
| D1 | 主叙事空心 | 去掉形容词后，主叙事还有真实动作和证据支撑吗？ |
| D2 | 中国语境失配 | 这个表达在老板、政府、客户、用户面前会不会尴尬、失礼、掉价、口号化？ |
| D3 | 行为改变断裂 | Step 2 定义的目标行为，现场机制真的能推动吗？ |
| D4 | 报名目标错配 | 邀约池、报名目标、到场目标、场地容量和餐饮数是否一致？ |
| D5 | 预算体验错配 | 预算押注是否支撑主场面和核心体验？钱是否花在不产生结果的地方？ |
| D6 | 赞助履约风险 | 承诺给赞助商的权益是否有资源、授权、证明材料支撑？ |
| D7 | 数据采集失败 | KPI 是否有采集点、负责人、工具和失败备份？ |
| D8 | 关键路径冲突 | 审批、设计、制作、搭建、彩排是否存在依赖冲突？ |
| D9 | 会中设计无效 | 峰会/圆桌/闭门会是否只排议程，没有推动认知、关系或销售？ |
| D10 | 事实来源不足 | 预算、案例、数据、政策是否被写成事实但没有证据等级？ |
| D11 | 需求被模板吞掉 | 按原 brief 逐条定位，哪些核心要求只有同名章节却没有实际内容？哪些愿望被偷换成硬约束或被惯例删除？ |
| D12 | 内容与串联空缺 | 不看策划口头说明，观众到底看什么/做什么、如何开始结束、为什么接下一单元？系列新内容与同作复演是否如实区分，复演是否有受众和排期理由？ |
| D13 | 文件交付虚假 | 按本次用途、交付承诺与成熟度核对实际内容底稿及文件要求，不以旧Step编号豁免已到期交付。已声称保存/交付的文件须检查真实存在、内容与可用性；未纳入本次范围的文件不强建，不能以目录、提示词、索引或改名文件抵交。 |
| D14 | 用途与成熟度错位 | 概念案是否被执行大表挤空，执行稿是否只有概念名词？创作拟案是否被写成资源锁定、制作完成或审批通过？ |
| D15 | 跨文件断裂 | 概念、方案、ROS、脚本、视觉、预算的单元内容、数量、时长、权益、版本与资源状态是否一致？ |
| D16 | 接手仍需重写 | 主创、设计、主持、供应商或传播团队能否据约定深度接手？按当前用途核对内容和接手条件，对已形成实际成品执行代表任务；不能以几个名称、截图表格或不可编辑文件抵交约定工作件。 |

按本次交付用途解释 D11-D16：概念评审不强求施工图，传播规划不冒充发布成品，复盘缺数据不能编成果。覆盖检查依据 `proposal-schema.md` 的需求追踪，攻击应给出具体要求/文件位置、事实或待验证依据，不因追求“大而全”增添用户未要的文件。

触发系列事件统筹时，按 [系列事件统筹](series-campaign-orchestration.md) 的“九、联动验收”把以下攻击挂回现有视角，不新增步骤、角色或暂停点：

| 既有视角 | 系列联动攻击 |
|---|---|
| D1/D12 内容 | 母题与场次能否形成整体；前后实际稿件相对该受众的已知内容增加什么，必要服务重复是否被误删；复演是否有真实受众与排期理由，下降是否被武断归因疲劳？ |
| D3/D15 传播与兑现 | 实际传播组合是否只记住明星而丢失项目、地点与到访信息；不同创作者的Brief/稿件是否只是通稿换口吻，从任一入口能否找到当前有效参与说明；满额/中断后宣传、预约与现场解释是否同步，有无虚构替代？ |
| D4/D7 人数与效果 | 邀约池、报名、到场、同时在场容量、人次、可识别去重是否混用；预测是否有依据与置信度，是否将曝光直接当客流或归因核销当增量？ |
| D5/D8/D16 资源与制作 | 共享场地、舞台、装置、嘉宾、摄影、剪辑、审核和权益有无同时占用或产能缺口；共享搭建、月度达人包及分摊是否重复计费？ |
| D8/D15 变更 | 改期或取消是否保留实际场次身份和记录；邀请、预告、素材、资源、预算、用户通知及下一轮内容是否同步检查，而非只改总排期？ |

运营检查引用 `metrics-flow.md` 与 `critical-path-delivery.md`：有效兴趣弱或入口异常时，继续/调整/暂停/恢复是否有证据、窗口、责任和履约依据，是否误把暂停追加投放当取消合同。复盘按 `data-capture-and-review.md` 攻击经验的适用条件、其他解释和重核触发；局部热点是否挤占全期制作、核心体验或商户服务。独立模拟只能证明稿件与流程的显著问题，不能生成真实记忆、自然传播或增量效果证据。

Step 7 核对当前底稿的关联与修法，Step 9 对实际创意、执行、宣传及适用扩展工作件复核；纯线上/局部任务只核对应范围。取一个复演、改期或资源取消的代表场景，定位受影响记录、预算及传播安排；存在关联字段并不证明能够正确处理变更。另按 `campaign-deliverables-and-playability.md` 五走读首次体验与内容失效，核对不出镜、不公开作品或安静观看的路径。修法须落实到实际内容、公式、排期或文件，不能只增加检查表。

## 四、收敛 + 严重度排序

- **多个角度独立打中同一弱点** = 关键发现，必改。
- **孤立冷门洞察**：先核对证据与影响；只有与本次用途无关或缺乏依据且不影响关键判断时才可搁置。有充分证据的关键失败，即使只有一个视角发现也必须修复。
- **根本缺陷**：优先找那个「一戳破整个结构就塌」的主要致命假设，避免罗列空泛意见；其他独立的关键失败仍逐项处理，不能为了只留一个而删掉。

输出排序：从「能毁掉整个活动」到「锦上添花」降序排。

## 五、补救方法

每条高严重度缺陷，给**可执行的修法**，不是「注意一下」：

- ❌ 「注意现场安全」 → 空话。
- ✅ 「依据场地核定的岗位缺口补齐人员，由明确负责人在实际报审/开场截止前完成适用检查；未满足开场条件时执行已确认的延期或限流安排」 → 可交接的修法，具体数值与条件仍须核实。

修法要能落到：加什么机制、换什么动作、删什么环节、补什么资源。

内容/交付缺陷优先补齐实际正文、规则、脚本、衔接或真实文件，不能用增加形容词、装饰图、目录、页数和审计表当修复。未知外部资源与已授权创作分开处理：继续完成可创作部分，同时列明事实缺口及影响。数量、规格、人员资质和时间要求须有本项目依据，上面的示例不是所有活动的统一现场标准。

**判词规则**：可修缺陷给具体修法、预案或降级版，并检查它们是否仍满足目标、资源和兑现条件。不能因新奇就先否定，也不能假定所有创意一定可修；无法在已知约束内兑现的部分明确未成立及需补证/决定，不以“加预案”冒充问题解决。

**唯一例外（攻击13）**：只有活动前提不成立、活动并非达成目标的合适方式时，才建议“不办原活动”，并给有依据的具体替代选项。改变已确认目标或方向时按研究生产循环一处理实质决定，不能把建议当成新委托已确认。终审沿用主文件判词：原活动记“需重做关键模块”，注明前提不成立及“不建议办/转非活动”的建议；不能为了交付而虚构原活动全案。其他可修风险仍给修法、预案与降级，不用此出口规避内容开发。

## 六、审查终局三问

1. 修完后，那个根本缺陷还成立吗？
2. 这是授权范围内的专业判断，还是改变已确认目标、主创意、承诺或预算的实质取舍？前者继续完成；后者先形成具体选项，只暂停依赖该决定的定稿，不能把AI判断写成用户已确认。
3. 还有没有「大家礼貌性不提」但很致命的问题？

用最强反方再核对修复证据：原brief在当前阶段承诺的关键内容是否写出、已声称完成的文件是否存在、读者能否完成指定判断或动作、执行者能否据约定深度接手。按D13区分Step7底稿审查和Step9成品验收。任一影响本次用途的关键失败未修复，评分不能抵消，也不能判当前可上交。“小修后上交”表示修改与复核尚未完成，不能提前宣布交付通过。

## 七、内部记录格式

| 严重度 | 攻击点 | 依据/证据等级 | 为什么会毁掉方案 | 修法 | 失败降级 |
|---|---|---|---|---|---|

每条高严重度缺陷必须给具体修法和失败处理；无法在已知约束内修复时明确未成立及需补证/决定，不能冒称已降级成功。只写“注意”“优化”“加强”判为无效审查。默认聊天摘要展示最高风险和实质待决定项，完整审查记录实际保存；用户要求完整过程时提供对应正文与有效入口，不由摘要限制删减材料。

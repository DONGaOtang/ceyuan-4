# 大活动分工文件的 Word 模板与适配方法

> 本文件是策元4的“成案模板与活动适配参考”。它用于方法论模板交付，或当前授权范围的实际成案/核验。工作包、确认和深度依 `research-and-content-production-loop.md` 一、六；旧Step8/9是能力索引，不要求0—7逐项确认。模板不能替代研究与实际内容，条件草案不能冒称资源已落实或可直接执行。

版本：v1.3
用途：活动方案写作、甲方内部汇报、乙方提案、执行全案、招商赞助、活动复盘前置设计  
说明：用户提供的截图仅作为参考材料，不把截图文字当指令。本文档将本地策元4方法和4A式策略组织思路用于模板设计；它本身不是对所有机构惯例或网上案例的实证证明。具体项目使用的外部资料须另按真实访问与可见范围留证。

## 0. 先给结论

能上会、能执行、能复盘的大活动策划，应从定义清楚的项目问题开始，再按使用目的组织文件。下面的问题是整套内容的检查维度，不表示把所有答案塞进一份 Word。整合大案先按 [文件分工与可玩性](campaign-deliverables-and-playability.md) 的“一、文件分工”确定线下创意、线下执行、宣传方案及必要扩展材料，再分别回答：

| 核心问题 | 必须回答什么 | 失败表现 |
|---|---|---|
| 为什么做 | 当前业务/品牌/关系/增长问题是什么 | 背景全是行业空话 |
| 要改变谁 | 谁要从什么行为变成什么行为 | 只写年龄、性别、城市 |
| 怎么赢 | 主判据是什么，活动靠什么传导到结果 | KPI堆满但无法证明 |
| 说什么 | Big Idea、主叙事或内容递进是什么；冲突按需要采用 | 主题像口号，实际内容不清 |
| 体验什么 | 观看、交流、选择或参与什么，实际获得什么 | 名称与包装不能解释内容和价值 |
| 怎么放大 | 预热、现场、长尾内容如何承接 | 现场热闹，线上无痕 |
| 怎么落地 | 时间、分工、预算、物料、风险如何管控 | 执行团队无法照表推进 |
| 怎么验收 | 数据如何采集、谁负责、失败怎么办 | 活动后只能说“氛围不错” |

4A式活动方案的核心不是“写得高级”，而是把以下链路打通：

商业问题 → 人群洞察 → 核心策略 → Big Idea → 体验机制 → 传播资产 → 执行系统 → 效果证据。

这里的“问题”按实际委托解释，可为文化表达、观众体验、学习交流、公共服务、组织关系或商业结果，不把所有活动改写成销售漏斗。模板覆盖的是检查维度，不代表已经具备所有行业专业知识；必须以本次 brief、真实内容、适用标准与证据决定写什么。需求到内容和实际文件的追踪使用 `proposal-schema.md`，不靠页数、标题齐全或固定文件数量判断完成。

## 1. 4A广告公司的产出逻辑

本文采用以下六类视角组织判断与内容；是否符合某机构实际流程须另核原文，不把本模板当作4A公司统一惯例：

| 层级 | 产出 | 判断标准 |
|---|---|---|
| Brief诊断 | 实际问题、替代解释、约束、成功标准 | 是否区分已确认诉求、推断与待核事项 |
| Strategy | 市场事实、竞争格局、目标人群、核心洞察 | 是否找到能驱动行为的矛盾 |
| Creative Platform | Big Idea、主张、语气、内容资产 | 是否能被一句话复述 |
| Experience Design | 现场机制、用户旅程、峰值时刻、终值动作 | 是否改变用户行为 |
| Amplification | 渠道矩阵、内容日历、KOL/媒体/私域承接 | 是否把现场变成可传播素材 |
| Effectiveness | KPI、数据采集、归因、复盘 | 是否能证明活动有效 |

4A逻辑对活动方案的最大价值是三点：

1. 把主题展开为有实际内容的创意平台，按本次任务连接必要的视觉、内容、体验、物料和沟通；媒体标题与销售话术只在相应任务需要时产生。
2. 把“用户画像”升级为“行为改变”。年龄和身份只是入口，关键是用户原来不做什么，活动后要做什么。
3. 让排期同时说明观众实际接触的内容、理解与选择、服务、完成状态及必要回访；情绪走向作为待核设计预期，不用标签代替发生内容。

| 9. 风险审查 | 策略、预算、合规、现场、安全、舆情 | Red Team风险表 | 只写“注意安全” |
| 10. 成案终审 | 老板/客户/执行/用户视角模拟 | 本次约定的可用载体；采用Word时交真实文档 | 方案无法支持约定的理解、决策或接手动作 |

## 3. 按用途裁剪的 Word 正文模板

以下是正式内容菜单。按本节归属表选取当前工作件要写的内容，再组织为可阅读的 Word；不能把全菜单机械复制进一份万能方案。方括号为待填字段，不要编造。

强叙事文化节庆、艺术展演或用户明确要概念案时，按 `narrative-and-concept-delivery.md` 完成概念阅读内容。整合大案由线下创意文件承载完整故事和单元内容，执行、宣传引用必要摘要，不额外复制概念案。活动介绍、故事正文和主要单元内容是对外成品，不属于必须移走的内部思考；下方占位字段不能代替内容深化。普通轻量活动和用户明确单项/单文件要求不默认增加文件。

模板交付可以保留填写示例；真实项目成案须填入已授权的策划内容。节目介绍、故事、机制说明、串联、主持示范和内容脚本不能一律留“待填”；仅用户掌握的事实、授权、名单及外部资源确认可保留待确认，并注明影响、责任和时间。概念拟案可完整创作但不假装资源已落实，执行交接稿须核实关键依赖。用途与成熟度按 `scope-and-commercial-boundary.md` 验收。

本模板不覆盖用户的明确格式选择。需要 Word 时为对应工作件生成真实 docx；需要 PPT、XLSX、PDF、HTML、脚本、图片等时依 `proposal-schema.md` 检查能力并生成相应载体。仅给正文、文件名或改扩展名都不算完成。同一执行用途内的排期、资源和预算表可放在执行工作簿分表；完整创意稿、宣传方案和宣传日历不得因此塞入执行文件。更多附件按独立阅读、维护/交接需要增加，不能固定每项目的文件数量。

未指定格式时也先按接手动作推荐，不因本文件名含Word就默认全部交Word。文字模板不能代替演示页的图文组织、工作簿的公式与筛选、设计源件的可编辑对象或现场调度表的cue；这些用途沿用 `proposal-schema.md` 的对应验收。这里只规定采用文字方案时的可裁剪内容结构，不代表所有行业最终文件的统一格式。

实际涉及线下内容、执行与线上传播的整合系列项目按 [系列事件统筹](series-campaign-orchestration.md) 的“一、触发、范围与阶段接入”“八、执行工作簿接口”接通信息关系，默认由以下三个有实际正文的工作件交付。纯线上、轻量和单项任务按实际职责裁剪，不强建空的线下文件。内部研究另设索引；研究报告、邀约到访、复杂体验细则、测量或周报有独立使用需要时再扩展，不预设固定套餐。单场活动仅有较长预热时不启用系列统筹；同作复演分别建实际场次，不以改标题虚构差异。

| 工作件 | 本模板主要取用内容 | 实际交付与维护边界 |
|---|---|---|
| 线下创意 | 项目判断/目标人群的创作依据，5-6节的总主题、故事开端/承接/结尾或适用内容递进、实际单元、参与体验、复访差异，以及可宣传角度、人物角色与资源内容潜力 | 完整故事与玩法正文在此维护；载体按概念审阅/演示需要选取。引用已核资源状态和预算条件，不写实际平台排产表或第二份预算 |
| 线下执行（含唯一总预算） | 8-10节的筹备至收尾、实际场次/人数口径、ROS/cue、岗位、物料、资源、采购付款、应急，以及现场采集和交接安排 | 同一执行用途的管理表默认可编辑 Excel，操作正文和脚本按需索引；线上费用也进唯一预算。以稳定编号连接创意原文和宣传兑现条件，不复制完整创意或宣传正文 |
| 宣传方案 | 7节及相关传播目标：线上分支、节点、逐日选题与信息、平台/账号、素材和审核交接、KOL/KOC任务、报名到访及后续参与入口、代表稿、自然扩散条件和对应测量 | 实际宣传排期在此唯一维护；需筛选/排产时使用宣传工作件自己的工作簿。引用创意单元、执行场次和 `cost_id`，不另建费用总表 |

第1-4节中各接手者需要的目标、依据和边界可以简短摘要引用；完整研究和测量是否独立成件由实际使用决定。封面分别写当前工作件名称、版本、负责人和关联入口；按 [文件分工与可玩性](campaign-deliverables-and-playability.md) 的“四、跨文件协同”用稳定编号、版本及有效相对链接定位唯一正文，不通过复制维护第二套故事、宣传日历或场次/资源/预算主账。

入口的主目录、角色、访问限制和补源规则统一引用 [检索路径库“四点六、行业入口与充分性”](search-paths.md)，本表仅说明材料用途，不维护封闭白名单。主页、搜索命中、正文已读、画面已看、摘图已取得和原生文件可编辑分别记录；目录外新来源可采用，登录/付费和甲方资料按关键缺口条件扩展。

尚未选择方向且确需新创意时，按本轮问题采用交叉网络或其他适用方法，形成足以比较差异的内容候选；已选母题、常规更新或局部修复直接深化，不强制重新发散。下表为可选输入，不是每轮动作配额：

对采用的实际内容检查下列适用问题，不把所有项目强制改成互动与公开传播：

1. 它改变了谁的什么行为？
2. 它推动哪个主判据？
3. 在本次现场、线上或混合场域，实际看见、理解或完成什么？

### 4.4 Red Team对抗审查

| 攻击问题 | 必须给出的修法 |
|---|---|
| 用户凭什么观看、到访或参加 | 对应实际任务的内容价值、入口、条件与服务，不强造稀缺 |
| 有自主表达任务时用户凭什么发 | 实际所得、作品、观点或服务信息；表达/不上镜均可选，材料与入口真实可得 |
| 存在购买/留资/签约任务时凭什么行动 | 有据价值、条件与接收端；不把销售漏斗加给观看或学习任务 |
| 老板凭什么批钱 | 主判据、预算取舍、失败降级 |
| 执行凭什么落地 | 时间表、RACI、物料、供应商、彩排 |
| 确有媒体任务时凭什么报道 | 可核新闻点、材料、人物本领或成果，未发生反应不预填 |
| 有赞助任务时赞助商凭什么投 | 可核权益、适用触达/经营目标与履约证明 |
| 适用条件如何核实 | 核具体事项、当地/平台现行原文与有权责任方；AI审阅不代替审批 |

连续传播另查：前后两轮实际稿件是否新增价值或具有合理重复用途，项目/地点是否被正确记住，受众阶段是否匹配，创作者实际交付是否同稿，任意入口是否有效。热度突增时走读容量与服务切换；投入调整时核合同与预算责任；复盘时核经验边界。检查须定位并修真实正文/Brief/工作表，不靠加一行“已考虑”通过。

### 5.3 按体量裁剪

| 用途 | 适用 | 内容组织依据 | 必要内容 |
|---|---|---|---|
| 概念审阅 | 早期方向判断、老板快速阅读 | 按实际阅读与比较任务组织；用户明确一页时遵其格式并说明内容边界 | 背景、目标、具体核心内容与体验、关键依据及风险 |
| 策划决策 | 对本次市场/体验方案作决定 | 按必要论证、内容和决策颗粒度组织 | 背景、目标、人群、创意、体验及适用的传播、执行、预算、风险、验收 |
| 执行接手 | 大型活动、跨部门、供应商落地 | 按岗位接手动作和必要操作深度组织 | 适用RACI、物料、供应商、ROS、核实与应急；采用互动、积分兑换等机制时附对应细则 |
| 竞标/招商/赞助 | 比稿、招商、对外合作 | 按实际评审或履约用途组织 | 具体优势与依据、适用权益/报价/履约；ROI仅在目标、数据与归因条件足够时提供 |

不设统一页数、标题字数或文件数量；篇幅由用途、内容与实际载体决定。必要内容必须充分展开，轻量活动也不能省掉适用的核心规则；用户只要概念、脚本、报价、传播或其他单一产物时按其用途裁剪，不能用长 Word 替代所需文件。概念/决策/执行/传播/招商/复盘按需要选取，不要求一项目全部输出。

以上用途裁剪不能覆盖整合大案的文件分工。整合大案按第3节分别交线下创意、线下执行和宣传方案；更多文件依据独立用途扩展，各文件的必要内容须实写，不把目录、引用和空表当作已交。

资料使用原则：

1. 国际案例拆“策略结构”和“效果表达”，不要照搬文化语境。
2. 国内案例拆“平台玩法”和“传播节奏”，不要照搬视觉包装。
3. 趋势资料仅支持其实际核验的对象、时间和样本范围，不能自动证明本案用户需求、可执行性或效果。
4. 所有预算、场地报价、法规审批、KOL报价、历史转化率必须针对具体项目重新核实。

本节网站是检索入口，行业概括是研究方向，均不代表已获取具体报告或证实当前趋势；不能把网站主页放进参考列表就宣称案例已验证。用于支撑判断时定位到具体页面/文件、日期、实际内容和适用边界，并写清借鉴的机制及不能照搬的部分。未验证的来源不替代本项目证据。

## 7. 最终自检

交付前逐条检查：

| 检查项 | 通过标准 |
|---|---|
| 实际阅读任务可完成 | 能在本次约定的阅读/汇报方式中解释为什么做、具体内容、取舍和适用预算/风险；不设统一分钟数 |
| 内容有实际价值 | 去掉视觉后仍有具体内容与受众所得；常规形式和复演可以成立，不强制创新机制 |
| 指标可采集 | 每个关键指标都有数据来源和负责人 |
| 创意能接续 | 采用内容有实际原型和必要依赖；执行/传播任务核对动作、素材、资源及预算，概念/观看/闭门用途不强加互动或公开传播 |
| 预算能解释 | 预算不是堆项目，而是支撑体验、传播、转化、风险 |
| 风险有可用处理 | 高影响适用风险有负责人、判定与真实可用的处理/备选；没有备选时说明采用边界，不用A/B标签冒充资源 |
| 适配实际任务 | 内容、受众所得、资源和接收端符合本次目标；组合形式可按真实需要使用，不凭名称排斥混合内容 |
| 思考与正文分离 | 上交版干净，内部推导可追溯 |
| 需求实质覆盖 | 已确认 brief 每项能找到实际内容和文件位置，部分满足/未满足明确列出 |
| 内容与串联完整 | 读者能理解主要单元实际发生什么及关系，名称、时长、字段和图片不能代替内容 |
| 成熟度不混淆 | 创作拟案、内容完成、资源落实、技术确认、审批通过分开标识 |
| 真实文件可用 | 所需载体已生成、可打开、关键内容可读，附件与引用有效，源稿与导出版本一致 |
| 执行能够接手 | 对于执行交付，规则、脚本、交接、资源与异常处理可用，不要求执行者重新策划 |
| 文件分工可用 | 按 [文件分工与可玩性](campaign-deliverables-and-playability.md) 的“五、验收”检查各独立用途的真实正文、唯一维护位置、版本和有效相对链接；执行 Excel 不承载完整创意/宣传案，宣传日历不复制进执行文件 |
| 系列联动可用 | 按 [系列事件统筹](series-campaign-orchestration.md) 的“九、联动验收”核对场次与复演、每日信息与素材、线上兑现、资源冲突与费用、人数口径和预测、改期连带；跨实际工作件走读代表性变更，并在唯一预算主账检查汇总重算 |

任何影响本次用途的关键失败，不能被总分、页数或文件数量抵消。模型评分只辅助方向比较，交付通过以需求内容、证据、数值、关联及执行条件满足本次用途为准。“小修后上交”意味着当前仍不可直接提交，须明确修什么并完成复核；没有真实生成所需文件则如实说明未交，不写“已全部完成”。

## 8. 一句话使用方式

拿到任何活动需求后，不要立刻写流程。先判定“这是什么局”，再问“要改变谁的什么行为”，然后用“主判据”倒推创意、体验、传播、执行和复盘。这样产出的Word不是模板填空，而是一套能被质疑、能被执行、能被验收的活动方案。

# Pitch Battle · 乙方竞标制胜页

本文件用于实际竞标、采购比较或招商说服任务，帮助回答客户为何选择本方案。乙方身份、报价或客户文件标签本身不触发独立页面；局部文案、执行表或既定方案更新只补当前需要的说服内容。相应用途的摘要或报价说明能够承载时，不再强建一页或一份文件。

## 一、触发条件

当前任务涉及以下实际取舍时加载相关内容：
- 需在竞标、比稿、采购评审中说明方案优势和采购匹配。
- 对外招商、赞助或合作需说明可兑现价值和投入。
- 客户明确要比较多家方案或要求成交说明。
- 需要解释报价价值与削减范围的后果；只查报价或整理执行记录不自动扩成竞标分析。

## 二、核心判断

先回答 4 个问题：
1. 客户真正想赢什么：老板认可、业务转化、传播声量、政企背书、渠道信心、预算效率，还是风险可控。
2. 竞争对手大概率会怎么写：常规主题、常规流程、常规预算、常规传播。
3. 我方洞察为什么更深：比别人更懂业务矛盾、人群动机、现场机制、传播资产或执行风险。
4. 我方哪一页最能打动客户老板：一句话、一个机制、一张图、一个预算取舍，还是一个风险预案。

## 三、Pitch Battle 页面格式

| 模块 | 内容 |
|---|---|
| 竞品提案预判 | 其他乙方可能给什么常规方案 |
| 客户真实胜负手 | 客户真正要赢的不是活动本身，而是什么 |
| 我方制胜点 | 我方区别在哪里，为什么不是模板 |
| 老板打动点 | 客户老板最可能记住哪一句/哪张图/哪个机制 |
| 不可替代资源 | 我方独有案例、供应商、创意机制、执行经验或方法 |
| 报价为什么值 | 按客户判断需要解释费用购买的内容、服务和保障，引用唯一预算主账；不由预算大小强制采用系统包装 |
| 压价应对 | 可砍项 / 不可砍项 / 砍掉后的影响 |
| 成交话术 | 项目经理或商务怎么讲 |

竞品预判标为假设，不伪称已看到对手文件；“不可替代资源”须有实际证据和本项目可用条件，没有独占资源时如实用内容设计与可检查交付证明。页面的说服材料围绕客户采购标准展开，不能取代作品/活动内容本身；用户只交指定文件时在相应正文表达，不另增未经请求的文件。

## 四、压价应对

| 类型 | 可砍 | 不可砍 | 砍掉后果 |
|---|---|---|---|
| 传播 | 对任务无实质贡献的渠道、素材或服务 | 支撑已承诺内容与有效入口的必要制作和维护 | 说明具体少覆盖谁、少解释什么或何处断链，不自动承诺声量变化 |
| 现场 | 不影响核心体验且可依合同削减的规格或服务 | 已核场域下的必要安全、接待与内容条件 | 按实际体验与服务能力说明影响，非所有项目都有核心仪式 |
| 执行 | 经依赖检查能够削减的占用或外包项 | 本次兑现所需的统筹、核验与保障 | 说明资源及履约影响，避免把未核人手直接称为冗余 |
| 创意 | 不再服务目标的辅助内容或表达 | 本次已确认核心内容及受众所得 | 说明所失价值；峰值、传播钩子仅在本任务确需时保留 |

表中是取舍检查的例子，不是固定可砍/不可砍清单。执行主账确认合同、已发生成本和后续可变投入；暂停发布、停止追加投入与取消合作分别处理，运营动作引用 `metrics-flow.md`。

硬规则：不能只说“预算越低效果越差”。必须说清砍哪项、影响哪一层指标。

## 五、简短 Pitch 的可选句式

需要口头成交摘要时，可用以下三项信息组织；长度按实际使用场景确定，不要求三句话或对立句式：

1. **客户问题句**：这次活动需要解决____，依据是____。
2. **我方方案句**：所以我们用____机制，把____变成____。
3. **支持依据句**：选择这套方案的依据是____，关键条件和剩余不确定性是____。

## 六、禁区

- 不要靠“我们经验丰富”自证。
- 不要把所有竞品都假设成很弱。
- 不要为了中标承诺不可控结果。
- 不要隐藏被压价后的质量损失。
- 不要把 Pitch Battle 写进客户看不懂的内部黑话里。

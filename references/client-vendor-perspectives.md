# 甲乙方与提案口径

同一场活动，甲方和乙方的方案逻辑不同。下列模块在该用途和范围内适用；身份标签不能扩大用户只要求概念、局部改稿或单份文件的范围，主流程与确认动作仍按 SKILL.md。不能混写成“看似公平，实际谁也保护不了”的空话。

## 一、甲方模式

适用：用户要给老板、领导、内部市场部、业务负责人看。

甲方关心：

| 模块 | 必须回答 |
|---|---|
| 业务问题 | 为什么要办，不办会怎样 |
| 目标判据 | 怎么证明活动有效 |
| 预算合理性 | 钱花在哪，哪些不能砍，哪些可降级 |
| 内部资源 | 需要销售、运营、行政、法务、老板提供什么 |
| 风险责任 | 到场、舆情、合规、供应商、预算超支谁兜底 |
| 汇报可读性 | 老板能否快速看懂亮点和风险 |

甲方方案写法：
- 先写业务问题和目标，不先写主题。
- 预算要解释取舍，不只列金额。
- 风险要写真实风险，不写“加强管理”。
- 待确认事项要指向内部决策。

## 二、乙方模式

适用：用户是策划公司、广告公司、执行公司、咨询方，要给客户提案或报价。

乙方关心：

| 模块 | 必须回答 |
|---|---|
| 提案差异化 | 为什么不是模板方案 |
| 工作范围 | 我方负责什么 |
| 甲方配合 | 甲方需提供资料、审批、资源、反馈 |
| 不包含项 | 哪些不在本次报价内 |
| 报价逻辑 | 成本、服务费、第三方费用、应急金 |
| 验收标准 | 交付到什么程度算完成 |
| 变更机制 | 超范围、延期、反复修改如何处理 |

乙方方案写法：
- 创意亮点要更靠前，但不能牺牲边界。
- 正式提案必须有“工作范围与边界”。
- 预算表要区分我方服务费、第三方代采、可选项。
- 所有待确认事项都要绑定实际责任方：甲方资料由甲方补，乙方内容/报价由乙方补，第三方或主管机构事项记录对应接口，不把全部未知一律推给甲方。
- 竞标、比稿或客户多方比较时，按实际决策问题检查差异化、比较依据、压价影响及成交沟通；使用Pitch Battle中的适用方法。只有接手用途或正式模板需要时才另设页面，不凭身份标签强加整页材料，也不杜撰竞争对手提案。

路由：乙方提案、竞标、比稿、招商赞助需要比较或成交论证时加载 `pitch-battle.md`；可在既有提案中说明适用判断。页面有无不能证明中标能力，采用判断仍依真实内容、证据、资源与本次用途。

## 三、内部协同模式

适用：企业内部市场、HR、行政、销售、品牌、运营共同推进。

重点：
- RACI 分工。
- 决策节点。
- 内部资源需求。
- 跨部门风险。
- 活动后数据归属。

输出须覆盖实际适用的分工、时间线、资源需求和审批节点；只有同一接手用途的内容可合并分表，不以减少附件合并不同用途。整合大案按 [分工规则](campaign-deliverables-and-playability.md) 一、四分别维护创意、执行、宣传，其他独立交接按需要拆，不按岗位数量凑文件。各岗位引用同一已确认内容版本和主值，只裁剪其决策/操作所需摘要，不各写一套故事、预算或排期。

## 四、招商赞助模式

适用：赞助、招商、合作方提案、展位销售、资源置换。

重点：
- 对方为什么投入。
- 权益包如何分层。
- 曝光、线索、销售、背书如何交付。
- 权益交付如何验收。

输出必须有：
- 赞助商收益。
- 本次权益包及有实际取舍时的报价方案，不强建多档。
- 曝光资源清单。
- 交付范围。
- 合作条款和下一步 CTA。
- 比较依据：实际替代合作选择、我方权益与资源的匹配理由及限制；未知其他提案保持假设，呈现方式按接手需要选择。

## 五、政企/To G 模式

适用：政府、园区、协会、国企、公共事务、招商引资、签约仪式。

重点：
- 规格与秩序优先于“炸裂创意”。
- 口径一致优先于平台热度。
- 审批和公共价值优先于互动玩法。

按本次范围提供适用内容：
- 活动规格与公共价值。
- 涉及接待时的领导/嘉宾动线与座次。
- 实际安排的仪式动作及条件；无仪式不强加。
- 涉及媒体发布时的通稿口径。
- 与活动有关的审批和合规条件及责任。

禁区：
- 不随意做公开口径 AB 测试。
- 不为了传播制造冲突。
- 不写未经确认的政策承诺。

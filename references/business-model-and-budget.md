# 经营模型与预算

本文件用于 Step 3 经营模型、Step 6 交付系统、Step 8 成案。目标是让活动的“钱、资源、回报、降级”说得清。

## 一、触发条件

命中任一项必须加载：

- 用户提供预算、报价、成本、收入、ROI、赞助、票务、销售线索、订货、GMV。
- 乙方提案、招商赞助、老板过会、年度项目、大型活动。
- 用户问“为什么值”“怎么省钱”“预算怎么分”“钱花在哪”。

## 二、成本模型

| 成本类型 | 包含 | 输出要求 |
|---|---|---|
| 固定成本 | 策划、设计、场地基础、基础搭建、基础 AV、项目管理 | 不随人数变化，先锁不可砍项 |
| 可变成本 | 餐饮、礼品、座位、胸卡、物料、人员加班 | 按人头或数量计算 |
| 半可变成本 | 摄影摄像、传播、嘉宾、安保、搭建升级 | 给档位或区间 |
| 应急金 | 天气、供应商、物料损耗、临时加项 | 依据已识别风险、金额暴露、计算基数和客户要求测算；依据不足时列待定及影响，不预设比例 |

所有金额必须标来源：用户给定、供应商报价、历史数据、benchmark、暂定假设。预算上限不等于可成交报价；明细写数量、单位、单价/测算参数、次数/天数、税费与差旅装拆等包含范围。每个核心内容单元要能找到相应成本或已确认可用资源，不能把免费借用资源当默认事实。

应急金的金额或比例须说明风险依据和计算基数；已知必需费用不能藏入应急金。同一费用只能计一次。排期、场数、版本、人数或内容范围变化时同步重算，不能沿用旧总价。

## 二点五、系列项目的成本关联

系列模式下另读 [系列统筹模块](series-campaign-orchestration.md) 六、八、九和 [分工规则](campaign-deliverables-and-playability.md) 一、四，线下线上整合项目由线下执行工作件维护全项目唯一费用主账，包含线上线下费用；纯线上项目由约定的实际执行/运营文件承接，不为预算强建线下文件。宣传或创意中的预算摘要/分析视图引用cost_id与版本，不再建第二个可编辑总账；同一执行用途可以分表，不因此合并创意和宣传正文。计价、来源、税费和应急金沿用本文件。

共用成本、逐场增量成本和线上费用分别列出，并为每笔费用分配稳定 `cost_id`。全期装置、基础搭建或月度达人合同只在成本主账计入一次；分摊到内容单元 `unit_id` 或实际场次 `session_id` 的金额只用于解释归属，不再次并入总额。复演按确认的增量计价，不把全套搭建逐场重复收费，也不把摄影、运输或演员复演视为天然免费。

合同跨多个场次时保留费用覆盖范围与交付量；拟邀估算、供应商报价、已确认合同分别标记。取消或改期保留原场次和费用记录，核对已发生、可退、违约/改期及新增费用后重算；释放排期资源不等于费用自动清零。共享资源的可用性和占用冲突由 `critical-path-delivery.md` 核对。

运营决定另外核对费用状态，和固定/可变/半可变成本类型分开：已发生且不可收回、已承诺但尚待履行、按条件可退/可调整、尚未批准的后续可变投入。记录合同/报价证据、已付与待付、取消或改期条件及待核金额；状态不明保持待核，不假设零损失。按 [运营决定](metrics-flow.md) 八暂停发布或停止扩投时仍检查未履行交付，合同取消与预算变更须按实际权限另作决定。分析视图引用同一cost_id，不把这些状态再加成一套成本。

## 三、预算方案比较

只有真实存在需要决策的投入与体验差异时才比较预算方案，档数按实际备选与用户要求确定；固定范围可以只交该范围的费用和风险。下列Lean/Base/Stretch为比较维度示例，不是默认三档配额或必须加价的动作：

| 档位 | 定义 | 适用 | 不能牺牲 |
|---|---|---|---|
| Lean | 最小可行活动 | 钱少、时间短、先试水 | 主目标、合规、安全、核心体验 |
| Base | 推荐方案 | 大多数正式活动 | 主叙事、峰值、数据采集、风险预案 |
| Stretch | 增强方案 | 有证据支持追加投入的项目 | 与追加费用对应的目标贡献、核心体验与履约能力 |

档位表中的底线为示意，按本案实际承诺与必要条件确定；不因推荐档位强加峰值事件、长期资产或全量数据采集。追加费用比较它解决的具体问题、效果证据与履约条件，不把价格高当价值高。

## 四、回报模型

按活动动机选择，不要全塞。公益、培训、内部和艺术内容的结果可为知识、服务、关系或文化理解；不得为凑ROI虚构货币收益。意向收入、已签收入、回款分别列明，资源置换估值不等于现金收入：

| 回报类型 | 可证明方式 |
|---|---|
| 票务收入 | 票价 × 售票数，区分早鸟/标准/团购/赠票 |
| 赞助收入 | tier 价格 × 预计赞助数，区分确认和 pipeline |
| 销售线索 | MQL/SQL 数、商机金额、会后会议数、CRM 回填 |
| 渠道订货 | 签约额、订货额、首款比例、回款周期 |
| 品牌资产 | 内容资产、搜索占位、媒体报道、UGC、私域标签 |
| 汇报价值 | 领导到场、媒体口径、政策/机构背书、内部共识 |

## 五、预算价值架构

高预算、老板过会、乙方提案不要只列明细，先解释价值系统：

| 系统 | 包含模块 | 解决的问题 | 预算占比 | 价值证明 |
|---|---|---|---|---|
| 进入系统 | 邀约、报名、入口、导览、动线 | 用户如何进入体验 |  | 到场质量、投诉下降 |
| 发生系统 | 峰值事件、互动、仪式、内容 | 为什么必须到现场 |  | 参与率、停留、传播 |
| 资产系统 | 影像、UGC、媒体、复盘、CRM | 活动结束后留下什么 |  | 内容数量、线索、报告 |
| 保障系统 | 项目管理、安全、合规、应急 | 怎么保证不翻车 |  | 准时交付、事故率 |

## 六、降级模型

涉及预算或执行取舍时，对可能影响核心承诺的条件准备适用降级；局部文字修改引用已有有效预案，不重建全套降级表：

| 触发 | 降级动作 | 保留底线 |
|---|---|---|
| 钱少 | 砍装饰、砍低效物料、降搭建规格 | 不砍安全、主场面、数据采集 |
| 时间短 | 并行审批/供应商/传播，减少定制物料 | 不跳过彩排和合规 |
| 人少 | 缩场地、改邀请制、做高质量小场 | 不硬凑人场 |
| 审批慢 | 准备保守版主题、备选场地、替代物料 | 不碰合规红线 |
| 到场低 | 先核对受众、入口、时段、承诺与数据；有证据后调整适用邀约、服务或内容，见metrics-flow八 | 不伪造热闹，不默认加投或增设直播 |

示例中的主场面、数据采集和彩排只保留本案适用且必需的部分；开放观看、纯服务或局部修订不为套表添加仪式和实验。降级后的承诺、范围、素材、资源和费用须能对应实际文件；到场不足不自动增加候补、免费票或追加宣传。

## 七、预算自检

- 分项加总必须等于总额。
- 应急金必须单列。
- 不可砍项必须解释原因。
- 可砍项必须说明砍掉损失什么；客户已明确必需的内容、场数和权益不能因压价自动删除，必须显式列出范围差异及受影响原步骤。
- 乙方方案要区分服务费、第三方费用、可选项和不包含项。
- 系列总额按成本主账唯一 `cost_id` 加总，分摊视图与逐场引用不再相加；核对费用覆盖的场次/天数、共用资产与实际增量。

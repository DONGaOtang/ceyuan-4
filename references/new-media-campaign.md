# 新媒体 Campaign 模块

当任务涉及线上传播、平台内容、达人、UGC、直播、私域或长期传播时，按实际范围完成对应内容与承接。完整 campaign 需要持续内容、生产、分发和反馈关系；单条文案、局部改稿或单项传播任务不自动扩成全案。

## 一、判断是否触发

命中任一条件即触发：
- 活动主要依赖小红书、抖音、视频号、公众号、微博、B站、私域传播。
- 目标包含需要线上内容或入口承接的报名、收藏、转发、评论、留资、购买、复购；仅有线下登记或交易不因此触发新媒体全案。
- 活动要产出短视频、图文、直播切片、达人内容或 UGC。
- 活动需要线上预热、持续发布或后续内容；多日活动本身不构成触发，也不强造爆发期。

新媒体 campaign 与系列活动分开判定：单场活动有一个月预热仍可只用本文件；需要多周统筹、多场次、轮换内容或持续运营时，另读 [系列统筹模块](series-campaign-orchestration.md) 的“一、触发、范围与阶段接入”“四、系列活动与邀请”“五、线上分支与逐日内容”。本文件继续负责平台语法、内容资产和制作交接，系列关系、标识及跨表关联沿用统筹模块。

整合系列大案另按 [分工交付与体验规则](campaign-deliverables-and-playability.md) 的“一、文件分工”“三、传播与人物”“四、跨文件协同”形成独立宣传交付：议题、传播节点、平台与账号、KOL/KOC 内容任务、素材、稿件和逐日内容表在宣传文件中维护。现场故事、体验结构、人物内容角色和潜在传播角度引用创意文件；场次、邀约合同、资源状态、制作产能、技术安排与唯一预算引用执行文件。宣传文件不把执行预算另算一遍，执行工作簿也不再默认容纳所有研究、创意与宣传正文；索引负责连接。单项或轻量需求按其范围交付，不自动扩成三份全案。

## 二、平台矩阵与平台语法

### 线上与线下宣发触点协同

按本案人群与目标，将实际采用的线上渠道和项目自有屏/海报/导视、商户、社区/社群、合作渠道等线下触点连接在同一营销路径。上述触点是可选例，不默认全部铺开、已获使用权限或已授权外联。每个采用触点写明：目标人群、出现位置/时间、传播任务、实际信息/稿件、为何在此节点、可信依据、行动入口与兑现端、物料/权限/安装或人员依赖、负责人及观察指标。曝光、路过、有效兴趣、入场和消费各按口径观察，不能仅因布点就认定带来新增客流。

宣传维护主张、稿件与节点版本；执行维护物料规格、采购、安装、接待占用和全项目唯一费用；招募到访运营维护实际预约、响应、提醒与变更通知。用共同单元/场次/资产标识和有效链接交接，不把制作采购正文塞进宣传文件。按真实预热、招募、解释、兑现展示或再次到访节点排期，不强造“爆发期”。

### 平台选择与表达

不能只列“发小红书、发抖音”。每个平台必须说明它在本次活动里承担什么角色、使用什么内容语法、承接什么用户动作。

以下是可调查的任务与表达组合，不是平台固定定位、当前算法结论或必选清单。先核对本案受众、账号与可获得资料，再形成自己的平台选择；官方规则与可用能力按 `search-paths.md` 定位当期原文。

| 入口示例 | 可核对的任务 | 可尝试的内容 | 本案需验证的条件 |
|---|---|---|---|
| 小红书 | 搜索发现、体验判断、攻略收藏 | 真实体验、路线、费用与细节、问题解释 | 本地相关受众、搜索与入口情况、实际内容表现 |
| 抖音 | 视听理解、内容发现、现场观看 | 示范、人物与过程、清晰解释、合适的直播或片段 | 开场能否讲清价值、素材和账号匹配、有效兴趣与接收端 |
| 视频号 | 内容发现、既有关系触达、直播或服务承接 | 人物解释、过程、预约说明、回放 | 目标人群实际使用、可用账号能力、传播与接收条件 |
| 公众号 | 完整说明、服务与持续内容 | 背景、议题、路线、规则、真实结果 | 读者来源、阅读需要、有效链接及维护责任 |
| 微博 | 公开讨论、节点信息、人物或媒体表达 | 有据观点、过程与结果、准确服务信息 | 是否存在相关讨论、参与者与话题的真实关联 |
| B站 | 作品观看、专业解释、过程或人物内容 | 演示、纪录、访谈、适合本题材的长短内容 | 内容深度、观看体验、创作者匹配及后续入口 |
| 社群/其他私域 | 获同意的邀约、答疑、提醒与复访 | 按需要提供参与信息、反馈和后续内容 | 触达授权、分层依据、提醒负担与回应能力 |

按人群、目标和生产能力选择必要渠道，不设主平台数量。单一渠道足够时直接使用；确需多平台时说明各自贡献、必要重复与资源来源。公开互动只能支持可见表现，不能据此填写后台完播率、受众画像或去重人数。

输出要求：每个被选平台都要写 `为什么用它 / 用什么语法 / 不适合做什么 / 测什么 / 产出什么资产`。如果只能写平台名，说明还没想清楚。

## 三、内容节奏

| 阶段 | 目标 | 内容 |
|---|---|---|
| 预热期 | 造期待、测钩子、拉报名 | 悬念海报、邀约话术、达人预告、报名页 |
| 内容集中发生/兑现期（如有） | 让对应受众理解现场内容与当前参与条件 | 实际片段、解释、适用直播、准确服务信息 |
| 长尾期 | 沉淀资产、复盘转化 | 复盘稿、金句切片、用户故事、销售资料包 |

每个采用阶段写：目标、内容形式、平台、责任人、发布时间及适用观察方式；轻量改稿不重建全套指标。

阶段之间由实际内容接续：预热提出活动确实回答的问题，现场提供相应证据或体验，长尾整理真实结果并承接后续。不能用三套互不相干的选题凑齐周期，也不能在活动前写成已经发生的成果。短周期或单次传播按必要阶段裁剪，未发生的现场素材标待采集。

有线上任务的系列项目，其核心分支在 Step 4—5 与对应内容同时形成；有线下体验时不能等所有线下活动排完才补发帖。每个分支说明用户为何愿意观看/参与、实际内容或服务提供什么回应、结果如何成为下一轮信息；观看、探访、攻略、直播和专业解读均可成立，不强制设置共创或任务。采用征集、投稿或线上任务时，截止、判定、实际兑现位置/页面、容量及无法兑现的处理须与真实规则一致；细则仍按 `activity-mechanism-search.md` 完成。有线下内容才核现场、商户与到访条件，纯线上核实际观看/投稿/反馈端和服务能力；无线上任务不强加分支。承诺与实际场次和资源状态共同校核。

## 四、内容资产清单

正式方案按已选平台、目标和交付范围列出实际需要的资产，并在相应项提供可评审内容：
- 短视频：区分选题、脚本提纲与完整脚本；关键内容至少有开场、主要信息/画面推进、证据或体验片段、结尾行动的代表脚本拟案，写清拟拍对象和素材状态。
- 图文：关键内容给实际标题、导语、主要段落或图序、事实依据与 CTA；仅有选题方向不得称图文成稿。
- 直播/切片：若本次需要，写出直播内容推进、具体可剪点、必须保留的上下文、素材取得与剪辑责任，不能凭尚未发生的直播伪造金句。
- 嘉宾表达：写议题与引语收集、核对和授权机制；拟稿须标“供确认”，实际引用绑定可追溯来源。
- UGC：若需要，写用户可表达的具体体验、参与说明和回收/展示方式；不强制分享、上镜或夸赞，观看型活动优先保护完整观看。
- 官方复盘/跟进：列应回收的事实、片段与结果，提供结构或明确为拟稿的可写部分；活动未发生时不得填实到人数、反馈、销量或合作成果。

资产数量按本次承诺与生产能力定，不要求所有媒介齐全。标准方案需用代表稿证明表达能成立；用户要求全部文稿或执行交付时，完成约定的每份稿件，不能以代表稿替代其余成稿。稿件中真实信息缺口单独标记；可以完成的观点、故事推进、场景和表达不应全部推迟到传播团队二次创作。

让内容落地的检查：选一条核心传播，读者能否看出“讲给谁—讲了什么实际内容—用什么素材支撑—看完去哪里做什么”。开场抓注意、情绪和反转是可选表达手法，不能用无关悬念遮蔽报名条件、专业信息或观看承诺。按 `creative-director-quality-bar.md`“项目与地点记忆”检查实际传播组合；持续内容按研究生产循环“四、新增价值与受众阶段”并排检查稿件并修订，不只检查选题名称。

素材 Brief 写清真实素材失败时的可用替代：例如已取得的过程示范、作品细节、专业解释、服务信息或延后采集；替代必须符合实际可得状态。可以拍摄示范和制作创作段落，不能用演员、拟稿或事先安排的评论冒充自然观众反应；现场未发生、授权未取得或没有有效反馈时，如实改选题，不制造“观众一致好评”。

## 四点五、传播外包接口

持续产出按 [研究生产循环](research-and-content-production-loop.md) 四、五接入：每条采用的机会可追到研究/视觉依据、内容原料、实际稿件或源件、采集/制作/审核与接收端。已核可用储备、未来待采集和备用分别记录；不足时查原料、采集、权限、工时或审核瓶颈并修改实际Brief/稿件，不仅增加日历标题。事实尚未发生不填成果，储备按实际节奏和时滞安排，不设统一每日数量或天数。

当传播由外部公司、达人/KOL 团队、媒体公司或甲方传播部门承接时，不能只写内容资产清单，必须写“可交接 brief”。

按本次已约定更新节奏建立交付包。包中的项目可以是导览/服务更新、现场素材、核实后的引语、获准使用的用户表达、直播片段或下轮预告；只列实际需要且能够取得的内容，不默认逐日重做地图或必有金句、UGC和直播。

| 交付对象 | 本项目约定条件 |
|---|---|
| 内容与版本 | 关联单元/场次/素材ID，实际Brief或稿件，新增价值或必要重复理由 |
| 数量及依据 | 本节点实际需要的数量；说明内容供给、合同、规格与产能依据，未知待核 |
| 形式与成熟度 | 原片/粗剪/终版/脚本/文案/授权记录分别标识；按使用位置约定规格 |
| 来源与依赖 | 已取得或待采集、必要上下文、授权及不可承诺内容、失败时可用替代 |
| 时间与接手 | 采集、制作、核实、审核及交付截止，接收方、责任人与通过条件 |

交付窗口从实际发布节点和制作时滞倒排，不统一规定活动后多少小时。日更活动按确认日期维护任务，非日更按实际内容节点维护；期限受合同或平台要求约束时写明依据。未知规格由制作方确认，不编造平台硬性要求。只写“短视频若干条”不是创作Brief，把选题清单命名为“脚本”也不是成稿。

## 四点六、系列逐日内容与邀请接口

逐日内容表覆盖实际确认的预热、运营与收尾日期，每一天至少有一项明确安排：讲给谁、当天信息主张/选题与要点、素材来源和取得状态、发布平台及实际账号、行动入口 CTA、发布/交接时间、制作与审核责任、内容成熟度。无公域发布、只采集素材或只做私域服务的日期也保留一行并说明原因；覆盖日期不等于所有平台天天发布。日历行引用相关 `unit_id`、`session_id` 和素材 `asset_id`；来源依据用 `source_id` 连接研究索引。纯线上内容不虚构线下场次。

日历、代表稿、完整文案/脚本、已生成素材及待发布成品分别标成熟度。默认逐日交付选题、信息要点和行动入口，关键内容给代表稿；用户要求全量成稿时才按约定扩展。逐日日历不能冒充同等数量的已完成文案，也不能把待采集现场素材写成已有。采集、剪辑、授权和审核截止回写资源排期，发生改期或取消时按统筹模块“二、关联对象与变更”检查预告、链接、素材、交接和已发布内容的更正。

艺人、KOL、KOC先按本次任务分工：演出、共创、专业解释、本地发现、体验记录、招募或召回，再研究与本地目标客群匹配的候选。执行中的邀请表沿用统筹模块“四、系列活动与邀请”“八、执行工作簿接口”，维护拟邀范围/数量、匹配依据、相关场次、档期/报价/权利状态及备选；宣传任务表引用同一资源标识，维护实际内容任务、受众与账号、素材取得、交付规格、发稿节点、CTA、审核和发布状态。不能仅按粉丝量选人、把候选名写成已确认阵容，或把同一合同在不同平台重复计价；不承担发布任务的艺人也不强塞达人发帖指标。

KOL 需要说明其专业解释、表演或观点怎样让目标受众理解并相信具体内容；KOC 需要说明其真实体验视角、生活场景或本地发现怎样降低到访判断成本。称谓和粉丝量本身不决定任务，普通参与者也不能默认算合作 KOC。合作内容、官方内容和自愿用户表达分开记录；合作 Brief 可要求说明体验、展示过程和提供准确服务信息，不能要求给出预设好评或保证自然扩散。每项任务核对适用场次、资源状态、内容权利、生产能力和下一步接收端，未落实则保留对应待办。

### 创作者实际接力（主定义）

将合作角色落实到实际Brief、代表稿和入口：准确事实与当前服务信息可以共用；各任务再说明所服务的人群、带来的解释/观点/本地信息/个人表达、所需素材、为何在此节点出现、独立可理解的前情及当前参与入口。数量、媒介规格和发布时间引用已确认任务及生产条件，不按KOL/KOC标签分配固定条数或内容形式。

审核时并排读关键合作稿和官方稿：若只有署名、标题不同而正文相同，判断是有目的覆盖不同人群，还是缺乏差异；必要重复保留理由，缺乏贡献则改实际Brief与稿件。将某人的下一棒理解为内容关系，不能要求用户追完多个账号才能了解活动。从任一采用内容出发走读到准确、可用的咨询/预约/到访信息；链接或权益待配置就标缺口，发布前修复对应入口或改为真实可用的行动。没有跨平台去重依据，不声称“破圈覆盖了全新人群”。

## 五、用户动作链

不要只写“提升传播”。要写用户下一步动作：

```
看到内容 → 产生兴趣 → 点击/收藏/评论 → 报名/预约 → 到场/观看 → 互动/打卡 → 留资/购买 → 分享/复购
```

每个动作都要有承接物：
- 点击：标题、封面、CTA。
- 报名：报名页、福利、名额、提醒。
- 到场：准确日期地点、交通与等待信息、预约提醒、可兑现内容及适用权益；保证金仅在本次确需且规则明确时使用。
- 打卡：现场画面、身份凭证、限定内容。
- 转化：优惠、销售话术、会后跟进。

该链是可选择的动作路径，不是每个用户必须走完的漏斗。根据真实目标选择终点：可以是读懂、预约、观看、形成判断、私下联系或自愿分享；不需要购买/留资的活动不强加。每个保留的 CTA 写明实际接收端、用户可获得什么、需要提供什么、回应或完成后会发生什么。链接、二维码、名额、福利及响应能力未落实时标待配置，不能把“扫码了解更多”当作已打通。

传播承诺须与方案中的内容、日期、规则、作品/嘉宾状态和参与条件一致；预告拟邀内容不得写成已确定阵容。若某传播点被用作主要到场理由，现场必须存在相应内容，不能用同主题背景板替代体验。

主要到访内容须回答用户的实际选择问题：为什么值得花时间来、哪个人适合、能看见或做什么、需要多少已知时间与费用、如何开始、满额或临时改变怎么办。先查信息可信度、受众匹配、体验价值、交通/预约摩擦与承接响应，再决定是否增加提醒或达人投放；不能把曝光不足视为所有到访问题的原因。

## 六、传播钩子

有传播任务时，用与实际媒介相关的问题检查传播角度：
- 用户发出去能显得更有趣、更内行、更有身份，还是更接近某个圈层？
- 这个画面是否只有现场能拍到？
- 用户一句话怎么解释“我为什么来”？
- 受众初次接触时，怎样及时理解继续观看或阅读的价值？

以上问题按本次实际媒介回答。愿意读完专业解释、收藏实用资料、继续看完整表演或私下发给相关人，也可能构成传播价值；不能把炫耀身份与强情绪视为唯一动机。闭门、内部、禁拍或不以传播为目标的活动写清适用范围，避免为内容素材打断核心体验。

潜在角度在创意文件提出，本文件将选中的角度写成可交接传播动作与实际代表稿。不能以两份文件各列一次“情绪、反转、打卡”证明已经完成转译。

## 六点五、正向议题与人物表达

有正向自然扩散或人物形象目标时，把每项拟用议题拆成实际内容链，而非先预定热搜或人设标签：

| 要素 | 宣传交付要求 |
|---|---|
| 公众表达理由 | 目标受众有什么自己的记忆、判断、疑问、成果或经验可说；不只转发官方口号，观众表达与参加活动均可选择 |
| 真实内容与人物证据 | 引用创意中的场景和人物角色，说明真实本领、选择、努力或可见变化；事实、拟创作剧情、待采集反应分别标注 |
| 节点接力 | 确定预告提出什么问题，示范/解释提供什么信息，现场如何回应，结果如何通向下一轮；对应实际单元、场次和素材取得时间 |
| 表达与观看入口 | 允许有价值的观看、评论、私下分享或成果展示，说明入口与回应方式；不以晒照、上镜或公开夸赞作为获得核心体验的必经步骤 |
| 角色与素材 | 官方解释事实与服务，适配的创作者示范或解读，真实参与者自选表达；写必采片段、必要上下文、采集/剪辑责任及失败替代 |
| 核验与修正 | 将官方发布、合作发布、真实自愿表达、反馈与传播数据分开；缺反馈时保留缺口，发现误读或现场承诺落差时修正文案与承接 |

人物形象只能由内容中的具体行为与可信事实支撑：拟塑造“认真、专业、亲和”等印象时，稿件须能指出观众可以实际看见什么，不能编造履历、苦难、金句或观众评价。既有名人案例的机制可以研究，是否出于幕后营销必须有相应证据；自发走红、策划介入和因果贡献未知时分别保留未知。戏剧创作可以使用人物与情节，不能作为真实经历报道。

复核一条实际传播：只看到官方内容而没有用户表达时，检查用户是否有自己的所得与话可说、表达入口是否方便、是否害怕被强制上镜或评价、素材是否完整以及承诺是否兑现。把这些作为待验证原因并提出下一轮可观察调整，不预先归因于算法或受众“不配合”。自然扩散是条件式预期，活动内容、现场兑现和有据可查的传播交付才是本次可验收项。

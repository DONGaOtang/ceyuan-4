# 实验验证层 · AB 测试 + 最小预检

用于当前机制、内容、执行或效果判断中的验证任务；旧 Step 5/7/8 是能力索引，不规定固定前后阶段。按 [持续研究与生产循环](research-and-content-production-loop.md) 选择本次需检验的关键不确定性并交回实际修改。核心一句话：**对抗审查找关键假设与失效条件，适用的真实验证提供反应证据；计划与内部模拟不能冒称实测。**

活动行业不总适合严格 50/50 AB 测试；预算、样本、周期、渠道和可比性可能受限。这里统一叫「实验验证层」，AB 测试只是其中一种。对本次高影响且证据不足的假设，选择成本、实测能力和决策用途相匹配的验证；已有适用证据可复用，不把会议室判断当市场反馈。

## 一、触发条件

本次决定依赖高影响、尚未解决的不确定性，且现有证据不足时，安排适用的核查或验证。检查重点可以是：

- 内容依赖受众愿意来、发、买、信或记住，但其实际所得、阻力或理解仍缺证据。
- 对抗审查发现会改变方案采用、兑现或预算的高严重度假设。
- 新机制、执行链路或效果声明需要在当前条件下核实。
- 已有研究、测试或实际结果出现矛盾，需要区分替代解释。

验证数量和类型按这些关键不确定性、可比性、成本与实测能力决定，不按档位、体量或“面向外部”自动强加；局部更新和每轮工作不必都实验。可用适用的原始证据、技术预演、内容试读或真实受众测试解决问题，不强造 AB。缺数据、样本、权限或资源时交未验证状态、具体下一动作与依赖；条件草案及独立工作继续。

## 二、实验对象

优先回答当前关键不确定性。需要判断完整传播组合的理解、项目/地点记忆或完整参与路径是否可用时，可以测试整组内容或完整路径；这类预检查可用性和理解缺口，不据此把效果归因到某一个变量。需要识别单项变化的因果作用时再选择匹配的对照设计。

| 假设类型 | 要验证的问题 | 可测试对象 |
|---|---|---|
| 来不来 | 受众认为到场是否值得，实际所得能否回应阻力 | 邀约内容、嘉宾相关内容、体验所得、交通/预约条件及真实可用名额 |
| 发不发 | 传播钩子是不是自嗨 | 海报标题、打卡点、话题名、短视频脚本 |
| 买不买 | 转化机制是否有效 | 权益包、优惠机制、成交话术、CTA |
| 信不信 | 背书是否足够 | 客户证言、案例、数据、嘉宾身份、媒体背书 |
| 记不记 | Big Idea 是否能被复述 | 活动名、主视觉、峰值仪式、结束动作 |
| 跑不跑得通 | 执行链路会不会崩 | 签到动线、互动机制、直播链路、彩排流程 |

## 三、实验设计格式

每个实验按所选验证层级填写这六格；访谈、读剧、走场、技术预演或非AB审查的“版本”可以是一个拟案与判定标准，不为填A/B强造第二版本。方案只写验证计划不等于已做实验，实际结果必须另有样本与记录：

| 字段 | 写法 |
|---|---|
| 假设 | 因为____，我们相信____会让____人群产生____行为 |
| 对象与比较 | 说明单项变化、整组内容或完整路径；拟回答什么，哪些差异不能单独归因 |
| 版本 | 比较实验记录各版本与共同条件；单方案预检记录真实稿件/流程版本和完成标准 |
| 渠道/样本 | 在哪里测，给谁看，样本从哪里来 |
| 判据 | 与决策匹配的主要判断及必要辅助/护栏；可量化值有测量手段，理解预检可用明确任务和观察标准 |
| 失败或不明确的处理 | 修复、补证/重测、条件采用、替代或暂停；关键承诺失效时说明可兑现处理 |

**硬规则**：

1. 单变量对照用于识别特定变化时保持其他关键条件可比；同时改变标题、视觉和权益只能比较组合，不能把差异归给其中一项。适用的多因素设计须有相应样本、分析与实施能力。完整路径、内容组合、技术预演不受单变量配额约束。
2. 判据要提前写，不要看完结果再改成功标准。
3. 活动小样本测试可以不用统计显著性，但必须标「方向性预检」，不能伪装成确定结论。
4. 严格 AB 测试要预设样本量、周期、流量分配和停止规则；不要偷看中途结果后宣布胜利。
5. 对未通过、结果不明确或实施失败预先说明后续处理：修复、补证/重测、条件采用、替代或暂停；不是每个预检都必须制造另一套活动。关键承诺失效时须有可兑现处理及责任人。

## 四、验证深度与实施条件

| 级别 | 实验要求 |
|---|---|
| 局部/低成本验证 | 围绕当前未解决的决定性问题做适用的试读、技术/执行预演或受众预检；证据已够时说明复用依据，不为凑数新加测试 |
| 多项关键不确定性 | 逐项选择可回答问题的方法，说明样本、可比性、成本、实施能力和采用标准；一次适用验证可回答当前问题，不要求传播与转化各做一个 |
| 高影响且具备实测条件 | 形成与风险匹配的计划：样本、渠道、周期、指标、护栏、决策阈值、降级及必要的分流/停止规则；用户输出突出本次关键动作、决策点与未验证限制 |

## 五、常见实验形式

- 邀约话术 AB：A 强调身份/稀缺，B 强调收益/福利，看点击、回复、报名。
- 海报标题 AB：A 情绪钩子，B 功能钩子，看点击率、收藏率、咨询率。
- 报名页 AB：A 短页直接报名，B 长页加强背书，看报名完成率和线索质量。
- 目标受众预检：按当前问题、招募能力和可解释范围选择样本，看实际拟案或方向，记录理解、愿来理由、阻力和误解；样本不足时明确覆盖限制，不设统一人数门槛。
- 销售/渠道预演：让一线人员走读实际话术与回应路径；经授权的真实联系反馈与内部演练分开。需要比较且有条件时才增加版本。
- 现场彩排验证：小规模跑签到、动线、互动、直播链路，记录卡点。

内容项目可在原有最小预检中做冷读/复述：不给作者补充，让读者说清活动是什么、主要内容、前后关系及带走什么；执行方按规则走一轮，检查是否还需现场猜测。模拟读者只能找表达缺口，不能冒称真实目标受众测试或验证成功；内容测试不要求强行转化为报名AB。

项目/地点记忆与到访理解可使用实际传播组合：记录读者先前是否接触或参与、此次看了哪些真实素材；不提示地问其记住的人物/活动/项目/地点、能获得什么体验，再让其找到当前有效的参与入口。保存原话、路径卡点与版本，按 [数据采集](data-capture-and-review.md) 二标实测或模拟。连续内容预检比较已看内容和本轮新增价值；重复服务信息仍可能必要，低反应还需排查分发、受众和时机。

## 六、回填规则

筹备或运营中取得验证结果后，按 [持续循环](research-and-content-production-loop.md) 五交回本轮补证、实际内容/服务修订、版本与再核验，不只写下次动作；缺结果保持未取得，不编验证结论。全期复盘再把「目标 vs 实际」与已取得的实验结论对照：

```
原假设 → 测试版本 → 测试结果 → 实际活动表现 → 条件性结论 → 条件复用/暂不采用/重测
```

写回 `output/case-library/` 或用户指定复盘文档时至少记录，不得直接写回 `references/` 方法文件。跑测偏差写入 `output/run-reviews/`，方法论改进建议写入 `output/improvement-log/`：

- 哪个假设被验证 / 被推翻。
- 哪个版本赢，为什么可能赢。
- 实验结果和最终活动结果是否一致。
- 如果不一致，是样本错、渠道错、执行错，还是现场变量改变。

适用条件、反证、重查触发和下一次最小核查按 [条件性复盘](data-capture-and-review.md) 六保存；不能将单次失败改写成永久禁用。影响在营内容和投入时按 [运营决定](metrics-flow.md) 八落实决定及恢复条件。

**验证记录要能追到依据、限制和实际修订；方法是否改进不能仅由实验数量、计划完整或自评分证明。**

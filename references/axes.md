# 四维推导轴（需求检查与定位）

供 Step 2 行为改变、Step 5 创意机制前加载。核心一句话：**用「七状态 × 两层对象 × 五形态 × 时空」四维检查清单可能遗漏的需求，并用本项目证据校准分类。分类框架不保证穷尽现实。**

> 本轴用于快速定位和检查，不替代第一性分析、实际研究与对抗核验。需求信号可提出初步分类，再以brief、参与所得和证据校准；有交叉或矛盾时展开必要分析，不能把一步查表结果当已验证结论，也不为分类新增固定审批。

## 一、活动类型 = 四维的一个组合

```
活动类型 = 七状态目的 × 两层对象 × 五形态 × 时空
```

先用四维定位；不能恰当归类时，保留用户实际需求，在项目记录里写扩展解释及适用边界，不因查不到就断言它不是活动。此轮仍执行原有查表与案例核对，不在用户项目运行中直接增改稳定方法论。

## 二、七状态目的轴（查表定位）

| 需求信号（用户原话里的词） | 状态 | 典型活动 |
|---|---|---|
| 「要卖货 / 冲 GMV / 转化 / 促活」 | 行为 | 促销、招商、直播带货、体验店 |
| 「要让人知道 / 记住 / 造声量 / 占心智」 | 认知 | 发布会、媒体会、内容传播、快闪 |
| 「要让人喜欢 / 认同 / 归属 / 留人」 | 情感 | 答谢会、年会、粉丝见面、品牌演绎 |
| 「要拉近关系 / 结盟 / 答谢 / 留客」 | 关系 | 私享会、酒会、政企对接、答谢 |
| 「要钱 / 要渠道 / 要人 / 要数据」 | 资源 | 路演、招商、招聘、数据沉淀 |
| 「要剪彩 / 揭牌 / 签约 / 授牌 / 上市 / 奠基」 | 身份 | 开工仪式、揭牌、签约仪式、授牌 |
| 「要运动 / 身体技能 / 急救操作」 | 生理能力（适用示例） | 健康跑、身体技能练习、急救操作演练；体检结果与健康目标分别核对 |

> 七状态 = 认知 / 情感 / 行为 / 关系 / 资源 / **身份** / **生理能力**。身份表达和身体技能可作为额外检查角度，不能由“剪彩、体检、培训”名称断定状态；专业学习可能对应认知/行为，体检可以提供身体状况信息，仪式表达也可能涉及关系和情感。

七状态是检视角度，不是互斥行业标签：培训可偏认知/行为，运动可兼关系/情感；以用户实际想改变的结果判断，不能把所有培训都解释成生理改变。仪式表达的身份必须已有合法/组织依据，象征动作本身不能创造真实资格。

## 三、两层对象轴

| 层 | 含义 | 例子 |
|---|---|---|
| 参与者 | 谁来现场 | 消费者 / 员工 / 媒体 / 领导 / 公众 |
| 受益者 | 谁最终获益 | 与参与者可能重合、部分交叉或分离；公益/环保/CSR 也需按真实内容与受益关系判断 |

分别判断「参与者是谁、受益者是谁」及其实际关系；确有分离或交叉时说明各自所得与可能冲突，不从公益、环保或CSR标签断定两者分离。

## 四、五形态轴（参与者与活动的关系）

| 形态 | 参与者角色 | 例子 |
|---|---|---|
| 接受 | 被动看/听 | 发布会、演讲、展览 |
| 参与 | 主动做/玩 | 快闪、体验店、游戏化 |
| 仪式 | 完成象征动作 | 剪彩、颁奖、签约 |
| 连接 | 建立人际连接 | 酒会、私享会、答谢 |
| 共创 | 产出内容 | UGC、挑战赛、内容共创 |

## 五、时空轴

线下 / 线上 / 混合 × 单次 / 周期。

- 「线上型」活动（Webinar / 线上发布会 / AMA / 虚拟活动）是「形态+时空」的组合，不是独立目的——它落进「时空轴=线上」+ 对应目的。
- 「周期型」活动（会员日 / 月度社群活动）落进「时空轴=周期」。

## 六、推导路径记录（按本次判断需要）

本次需要重新判断目标、对象、参与形态或时空安排时，内部可用以下路径记录检查结果，也可用更贴合问题的表或短文；局部标题、文案和已有内容的修订引用已确认依据，只更新受影响项，不强建四维全路径。默认写入过程记录；正式方案仅呈现帮助本次选择的内容或用户要求展开的部分。路径示意：

```
[七状态] → [参与者/受益者] → [形态] → [时空]
例：行为 → 消费者/消费者 → 参与 → 线下/单次
例：身份 → 领导+员工/组织 → 仪式 → 线下/单次（剪彩）
例：资源 → 公众/环境 → 共创 → 混合/周期（公益）
```

这条路径随目标/内容判断形成并在实际审查、交付和反馈中校正，不等旧Step7/8。运营中的新证据可触发补研究与实际内容/服务修订，保留对象、依据和版本；结束后再归档到 `output/case-library/` 或用户指定复盘文档。完整循环按 [研究与内容生产](research-and-content-production-loop.md) 五、六，不把分类记录当实际内容或成效证明。

## 七、用法（定位与内容核对）

1. **查表定位**：拿需求信号词，对「七状态」表定位目的，再补「对象 / 形态 / 时空」。
2. **查案例锚点**：定位完，去 `event-types.md` 查对应类型的「核心要素 / 成功判据 / 翻车点」落地。

**分工**：axes.md负责检查可能遗漏的维度，event-types.md提供类型与内容检查线索；两者均不能代替当前内容创作、资源确认或真实效果证据。按问题选适用路径，不把所有分类交叉组合强写进每份方案。

# To B 销售协同链

To B销售活动是销售推进系统的一段，有销售目标却没有销售协同链的方案不完整。纯技术交流、学术研讨、培训或内部伙伴协作先核对是否有销售任务；无此任务时对应交付资料、问题回应与后续协作，不虚构SQL/报价或强制收集采购预算。下面的原销售动作仅在适用时执行。

## 一、完整链路

```
目标账户 → 邀约名单 → 销售话术 → 必要信息与意愿确认 → 到场识别 → 适用交流 → 线索评级 → 按约定节点跟进 → CRM 回填 → 后续评估或商机推进
```

## 二、适用销售接口

有销售任务时按实际链路填写以下信息；不适用的动作说明采用的承接方式，未取得事实保持待核，不为填表杜撰预算、身份、采购周期或意向。

| 字段 | 写法 |
|---|---|
| 目标账户类型 | 行业、规模、区域、采购阶段、存量/新客 |
| 人群角色 | 决策人 / 影响者 / 使用者 / 采购 / 技术评估人 |
| 邀约名单来源 | 销售名单、CRM、渠道、协会、老客户转介绍、广告线索 |
| 销售邀约脚本 | 不能只发海报，要有角色化利益点 |
| 报名筛选 | 只收本次接待和已明确销售任务所需信息；公司、角色、需求、项目阶段按必要性选择，未知预算不强造 |
| 到场识别 | 签到标签、胸卡颜色、座位区、销售认领 |
| 现场互动 | 提问、圆桌、私聊、体验、需求卡、意向表 |
| 线索评级 | A/B/C 或 MQL/SQL，写清判定标准 |
| 会后跟进 | 各类需求的响应承诺、实际截止、负责人及失败交接 |
| CRM 回填 | 字段、负责人、截止时间 |
| 二次会议 CTA | 预约诊断、方案演示、报价会、POC、拜访 |

## 三、销售邀约脚本

按角色写，不要一套话术打所有人。

| 角色 | 邀约利益点 |
|---|---|
| 决策人 | 行业趋势、预算效率、风险、同行案例、战略判断 |
| 影响者 | 方案可行性、内部推动材料、成功案例 |
| 使用者 | 具体痛点、效率提升、体验、培训 |
| 采购 | 成本、服务边界、供应商稳定性、验收 |
| 技术评估人 | 架构、兼容性、安全、实施路径 |

邀约脚本须给可以实际发送的文字拟稿：对象困境、具体议题/演示、到场收益和清楚回复方式；不能只列“关注效率”。跟进资料应对应会中实际问题，至少有承诺内容的正文/样稿及取得方式，而非空白“白皮书”文件名。拟写不等于已对外发送。

## 四、线索评级

按业务真实采购周期、需求成熟度、参与者意愿及团队标准定义，以下角色是可选分层，不预设采购月数或响应小时数：

| 等级 | 标准 | 会后动作 |
|---|---|---|
| A / SQL | 符合本业务已约定的销售受理条件，如明确项目与可推进的评估需求 | 指定销售按可履行承诺响应，确认下一步和时点 |
| B / MQL | 有适用需求，仍需核实必要条件或评估角色 | 根据已同意的联系安排提供对应资料并确认需求 |
| C / Nurture | 暂无推进条件或周期较长，仍有后续内容需求 | 仅在同意范围内提供适用内容，并设置退出或更新方式 |

## 五、约定跟进节点

| 节点 | 动作与时间依据 |
|---|---|
| 首次回应 | 根据现场承诺和需求紧迫性指定负责人、截止及实际材料；可包括感谢、资料取得和问题回应 |
| 需求核实 | 按参与者意愿与资料就绪时间确认下一步，未就绪说明取得路径，不以空白文件充数 |
| 后续评估或培育 | 双方约定必要会议、演示或内容；回填真实状态及下次动作，不把所有人强推入二次会议 |

窗口在本项目排期内写成明确日期/时间或响应约定，先核实接手团队能力；若失约，说明新时点和替补责任。不同线索可以不同节奏，不以统一时限替代业务判断。

## 六、CRM 回填字段

按本次业务必要性核对以下候选字段：
- 账户名称。
- 联系人姓名与角色。
- 行业/区域/规模。
- 需求关键词。
- 预算或采购阶段。
- 活动互动记录。
- 线索评级。
- 归属销售。
- 下一步动作。
- 截止时间。

上述为供核对的字段范围，实际CRM按已确认业务必要信息、可取得记录与接手系统设定；未知预算、采购阶段标未取得，不能将提供预算作为所有参会者的门槛。评级条件、反馈与后续动作记录真实状态，活动互动不能直接判为采购意向或收入。

## 七、验收标准

有销售任务的 To B 交付须能回答：
- 谁邀约。
- 邀约谁。
- 用什么话术。
- 到场后怎么识别。
- 会后谁跟进。
- CRM 填什么。
- 如何推进到二次会议或商机。

只有活动当天流程，没有以上链路，判为不完整。

# 报名、票务与到场系统

本文件用于有外部报名、票务、邀约、签到、候补、到场率要求的活动。

## 一、触发条件

- 发布会、峰会、论坛、展会、招商会、私享会、快闪、市集、直播、线上/混合活动。
- 用户关心报名、到场、售票、邀约、名单、签到、留资。

触发后先核对入场机制。开放街区、自由观看或无需预约的活动不能只因活动类型命中，就强制增加报名、检票或留资；适用性记录保留，改用清楚的到场指引和现场观察。提醒时点依活动周期、用户所需准备、团队能力与已同意触达方式约定，不意味着已经发送。

## 二、报名/到场漏斗

采用报名/邀约机制时，按真实路径拆分；未采用的阶段不虚构：

```
目标人群 → 邀约池 → 点击/回复 → 报名 → 确认 → 到场 → 现场互动 → 会后跟进
```

| 阶段 | 指标 | 责任人 | 数据来源 | 失败动作 |
|---|---|---|---|---|
| 邀约池 | 名单数、匹配度 |  | CRM/私域/渠道 | 补名单/换渠道 |
| 报名 | 报名数、完成率 |  | 表单/小程序/票务平台 | 降低表单阻力 |
| 确认 | 确认率 |  | 短信/私信/电话 | 核对触达、参与条件与真实阻力后调整服务信息 |
| 到场 | 到场率、no-show |  | 签到/扫码 | 按容量、已约定释放规则与缺席依据选择候补或适用提醒 |
| 互动 | 互动率、留资 |  | 现场任务/问卷 | 优化动线 |

## 二点五、人数口径与跨场统计

系列项目另读 [系列统筹模块](series-campaign-orchestration.md) 的“四、系列活动与邀请”“七、测量与每周调整”“八、执行工作簿接口”，人数的专业定义仍以本文件及已确认的项目测量方案为准。

| 口径 | 应怎样记录 |
|---|---|
| 邀约池 | 可触达且与目标匹配的候选人数；已邀、回复、确认分状态，不等同预计到场 |
| 报名人数 | 指定活动/场次的有效报名，记录重复、取消与候补处理；一次登记多人须说明按订单还是人数计 |
| 预计到场 | 依据报名、确认或可核实历史数据作预测，注明来源、时点与假设；无依据保持未知 |
| 实际到场 | 指定场次/日期、入口和采集方法下观察或签到的人数；进出次数与人数分开 |
| 同时在场容量 | 某点位/空间同时可容纳的已核实上限；不等同全日累计人次或报名上限，未知时待场地方核实 |
| 累计参与人次 | 按已定义的参与动作累计的次数/场次人次；一个人多场参与可多次计，不称去重人数 |
| 可识别的去重人数 | 在合法、已约定且可覆盖的识别范围内去重，注明覆盖范围与未识别部分；无法识别全体时不推称全项目独立访客 |

内容单元用 `unit_id`，实际场次用 `session_id`；同一节目复演三场逐场记录名单、权益、容量与到场，跨场总参与人次与去重人数分别汇总。报名/确认/实到/核销的分母、统计窗口和适用人群显式记录，不把艺人、工作人员、媒体和普通观众混成同一到场率。多人合报、重复进出、跨场复访按项目已确认的可识别方式处理，未覆盖的部分保留限制。

开放街区、自由观看活动不用报名漏斗预测自然客流，改用明确点位、时段和方法的现场观察、计数器或项目可提供数据；经过、观看、参与及商户到访分别界定。计数方法无法去重时只报该方法支持的次数/估量及限制。到场效果预估不得由曝光乘任意转化率得到；预测与真实采集分别标状态。

## 三、表单字段原则

报名表要少而准：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 姓名/称呼或预约标识 | 实名核验、签到或沟通确需时填写 | 依真实入场机制选择必要识别方式，不为匿名观看强收姓名 |
| 手机/微信/邮箱 | 按场景必填 | 只收必要联系方式 |
| 公司/职位 | 对应业务确有必要时填写 | 用于所需身份核验或已明确销售任务，不因To B标签自动必填 |
| 参与方式 | 混合活动必填 | 线下/线上 |
| 需求/兴趣 | To B/课程/招商建议 | 用于会后跟进 |
| 餐饮/无障碍需求 | 线下活动按需 | 不得过度收集敏感信息 |
| 营销/赞助数据授权 | 涉及后续营销或赞助数据共享时必选 | 不得默认勾选 |

## 四、票务与权益

| 类型 | 适用 | 注意 |
|---|---|---|
| 免费报名 | 私域、品牌活动、社区活动 | 依据可比记录评估缺席风险，按容量和服务安排适用提醒、确认或候补 |
| 付费票 | 峰会、课程、演出、展会 | 需退款、发票、票种规则 |
| 邀请制 | VIP、闭门会、政企、私享会 | 不做公开报名页，重视 1v1 邀约 |
| 早鸟/团购 | 峰会、展会、课程 | 明确截止时间和权益差异 |
| 赠票/媒体票 | 嘉宾、媒体、赞助商 | 单列配额，防止挤占核心人群 |

每种票/邀请要说明实际可获得的内容、时间/场次、使用者、容量/库存来源、核验、取消/退款处理和异常联系途径；有分场预约时与演出日、作品、可用席位分别计数。内容或服务未落实时不得印入权益。

## 五、no-show 管理

采用免费报名/预约的活动设计 no-show 预案；无需报名的开放活动不造候补名单：

- 根据报名距活动的间隔、参与者准备需求、状态变化及同意触达方式约定提醒节点；减少无新服务价值的重复，改期、满额等变化单独处理。
- 重要嘉宾或 To B 决策人用 1v1 确认，不只群发。
- 名额有限且需要释放时设置适用候补机制，明确触发、通知和确认规则；无此需要不造候补池。
- 需要更可靠确认时比较回执、候补释放等方式；保证金或专属座位只有在真实必要、资源明确、退还/使用规则可兑现并经适用决定后采用，不按价格或小场标签默认增加。

## 六、签到与失败备份

| 项目 | 要求 |
|---|---|
| 签到方式 | 二维码、名单、胸卡、手环、人工确认按场景选择 |
| 峰值排队 | 预估高峰，设置快慢通道 |
| 身份识别 | To B 可用胸卡颜色/标签区分角色 |
| 系统失败 | 离线名单、手写胸卡、备用网络、纸质签到表 |
| 数据回收 | 按工具访问、隐私要求与运营判断窗口约定导出时点和负责人，与可匹配报名表核对；不能匹配的部分单列 |

## 七、交付清单

有报名/票务活动按实际需求准备下列交付表。表单字段的“必填”只在对应业务必需时采用；营销/赞助授权不得等同于观看资格，也不能把内部评级公开贴成观众身份。聊天可给关键结论和卡点，完整工作表随完成保存和核验；执行交付所需表必须进入可访问的执行附件或工作簿，不能仅藏在思考过程文件或等旧Step8再交。系列项目按统筹和分工模块分配给实际接手用途，不按表的数量拆文件。

| 表 | 内容 |
|---|---|
| 报名漏斗表 | 各阶段目标、负责人、数据源 |
| 表单字段表 | 字段、必填、用途、合规说明 |
| 提醒节奏表 | 时间、触达方式、话术方向 |
| 签到方案 | 入口、人员、设备、失败备份 |
| 到场与服务调整 | 到场不足时核对受众、入口、时段、承诺与数据；按metrics-flow八决定实际服务、内容或适用招募调整，不默认补人扩投 |

场次改期或取消保留原 `session_id`、名单与状态记录，核对报名入口、权益时间、候补、提醒、退改和通知责任；改新时间不能视为原报名者自动确认新档期。动作与通知草案可以准备，实际联系和发送按已有授权执行。

需求突增、目标点位满额或服务中断时，引用 [接待状态联动](critical-path-delivery.md) 八点六的确认状态与截至时间，核对预约库存、候补、排队、已出发/已到场用户说明、现场入口及可兑现替代。不能把满额体验继续宣传为随到随玩，也不能将局部限制写成整个项目关闭；恢复报名按指定负责人已核实的条件执行。
